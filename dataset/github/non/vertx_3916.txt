Wrong implementation of how to identify cookies
### Version

Version: 4.0.3

### Context

[RFC 6265 HTTP State Management Mechanism, 5.3 Storage Model, Step 11](https://datatracker.ietf.org/doc/html/rfc6265#section-5.3) defines the tuple (name, domain, path) as the cookie identifier. 
However, the implementation of [Http1xServerResponse](https://github.com/eclipse-vertx/vert.x/blob/4.0.3/src/main/java/io/vertx/core/http/impl/Http1xServerResponse.java#L787) and [Http2ServerResponse](https://github.com/eclipse-vertx/vert.x/blob/4.0.3/src/main/java/io/vertx/core/http/impl/Http2ServerResponse.java#L716) use only the cookie name as identifier.

### Steps to reproduce

1. Set two cookies with the same name but different path in a response header with
```java
public void handle(RoutingContext ctx) {
  Cookie cookie = Cookie.cookie("SOME_NAME", "foo").setPath("/");
  Cookie sameCookieWithDifferentPath = Cookie.cookie("SOME_NAME", "bar").setPath("/somePath");

  ctx.response().addCookie(cookie);
  ctx.response().addCookie(sameCookieWithDifferentPath);
  ctx.response().end();
}
```
2. Expect 2 cookies on the client, but only get 1.
