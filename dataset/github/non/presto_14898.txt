Incorrect time value(timezone converted) on filter node in ConnectorPlanOptimizer
Take Druid connector as example, In DruidFilterExpressionConverter when encounter filterNode,
it converts the timestamp(long) to string as following:
            SqlTimestamp value = new SqlTimestamp((long) ((ConstantExpression) argument).getValue(), session.getSqlFunctionProperties().getTimeZoneKey());

SqlTimestamp requires the first parameter in UTC, but the actual value on filter Node is still NOT converted to UTC. 
The root cause is: the time value on filter node does not converted correctly before go into ConnectorPlanOptimizer.

It's better to optimize this time value on filter node before go in to ConnectorPlanOptimizer.
