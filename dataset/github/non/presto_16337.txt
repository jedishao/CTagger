Optimize reading protobuf footers
When reading super wide tables (e.g., thousands of columns), the reader will spend significant amount of CPU on parsing footers. Even we are to select a few columns out of the super wide table, the footers have to be fully decoded. A [hacky fix](https://github.com/highker/presto/commits/cache) to stripe and filter footer cache can improve CPU utilization by 40+%. Note that the fix is just a hack to workaround the expensive parsing of large protobufs. Overall, we need **a more efficient method to decode protobufs or cache the decoded protobufs on disk with fast access**.

The flamechart shows the stacks for `readStripe` only, we are spending 30% CPU. The reason is that we have 3K columns, which ended up with 10K streams. To parse and cache these 10K streams per stripe is going to kill both CPU and memory; not to say we have about 10K stripes to read per machine. That will give us 100M stream objects to cache per machine.

Suppose we blindly cache these 100M objects, then our memory will look something like below with about 20GB used for it.

Also, all these objects are row-based. We store them with maps. That will stress out JVM GC + extremely high CPU lookup cache miss. The follow flamechart shows if we cache them all. We will significantly reduce readStripe CPU but ended up with GC overhead.
