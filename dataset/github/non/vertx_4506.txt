Extra fields while deserialization of request body as Json.
### Questions

Extra fields are appended in Json, while using `routingContetext().body().asJsonObject()`. is this something done purposefully or some bug in the serialization/deserialization of the body as JsonObject()?

I am not sure whether its a bug or this behavior is expected.

### Version

4.3.2

### Context

While getting my request body `asJsonObject()` through RoutingContext, I encountered some extra fields returned in JsonObject. 

### Do you have a reproducer?

Sending below Json as a request body in my REST API and trying to get this JSON in my API verticle as JSON using `routingContext.body().asJsonObject()`
```
{
    "type": "Query",
    "entities": [
        {
            "id": "abc"
        }
    ],
    "geoQ": {
        "geometry": "Point",
        "coordinates": [
            72.886055,
            21.224406
        ],
        "georel": "within",
        "geoproperty": "location"
    }
}

```

The below json is returned  for `routingContext.body().asJsonObject();` call

```
{
  "type": "Query",
  "entities": [
    {
      "id": "abc"
    }
  ],
  "geoQ": {
    "geometry": "Point",
    "coordinates": [
      72.886055,
      21.224406
    ],
    "georel": "near;maxDistance=100",
    "geoproperty": "location"
  },
  "ids": [
    "abc"
  ]
}

```

> noticed extra ids field, while just calling `routingContext.asString()` returns correct json string
