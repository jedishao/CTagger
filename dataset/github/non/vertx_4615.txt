A key HTTP2 performance loss has occurred
While exploring the code base, I noticed that the gRPC transport layer had been replaced by the Vert'x HttpClient. Although this change is functional, it has resulted in the loss of a crucial performance feature that was developed by the Google team. The original gRPC client was capable of aggregating multiple DATA and HEADER frames into a single HTTP2 packet.

In this scenario, I am issuing two gRPC client requests in rapid succession. 

gRPC stub aggregate HEADERS[3] + HEADER[5] + DATA[3] + DATA[5] of the two client request into a single HTTP2 packet.
![image](https://user-images.githubusercontent.com/6957561/218431756-a6c7d777-e423-4521-a58d-0698ffddb269.png)

HttpClient in grpc-client split the two requests into four separate HTTP2 packets.
![image](https://user-images.githubusercontent.com/6957561/218432622-2f222418-d904-453a-bc34-e0a659d610ea.png)

This creates a substantial overhead as each packet requires several additional TCP and HTTP headers. The total amount of bytes sent and received has significantly increased.
