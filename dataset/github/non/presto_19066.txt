The current native docker image build approach does not support CI properly
Here is the current Dockerfile: https://github.com/prestodb/presto/blob/master/presto-native-execution/scripts/release-centos-dockerfile/Dockerfile

There are 2 major issues from CI's perspective,
1. git clone of Presto repo inside docker image
   For a PR, the CI process usually merges the base branch (say master) into the feature branch, before launching build/test stages. The Dockerfile is already part of source code repository, we should reuse the already cloned repository.

2. development environment setup inside the same Dockerfile to build the Prestissimo/Velox code.
   Usually the development environment is stable, with very infrequent update. The better way is to pre-build this environment into a docker image, like what Velox development team has been doing -see this prestocpp/prestocpp-avx-centos:kpai-20221018.

Based on the above reasoning, I propose we remove git clone from the Dockerfile and also break it into 2 Dockerfiles, one for development environment, and another to build Prestissimo/Velox source code.
