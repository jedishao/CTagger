Optimize reading single column from a struct
We are seeing 2x CPU time difference between reading a top-level column and a subfield in a struct 2 levels deep. 

```
SELECT c FROM t;

SELECT a.b.c FROM t;
```

There are 2 sources of inefficiency:

- com.facebook.presto.orc.StripeReader#readColumnIndexes extracts statistics for all columns in a struct, not just the ones used by the query
- Dereference projection is using as much CPU as scan because is it going row-by-row and using BlockBuilder.

See #13817
