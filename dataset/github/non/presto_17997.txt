presto on spark shuffle tuning
We using spark3.1 to submit "presto on spark" application on yarn with the following configuration
```
--master yarn
--executor-cores 4
--num-executors 200
--executor-memory 20g 
--conf spark.task.cpus=4
# directory memory
spark.executor.memoryOverhead   8192
```
But when the shuffle data is large, then the executor of spark is easy oom, So, we have any secret sauce to tuning this situation？
