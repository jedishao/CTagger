flush_metadata_cache procedure in Hive connector does not check user data access
Opening an issue for this topic to discuss. Currently the flush_metadata_cache procedure does not check any user permission for the underlying table or schema before running the procedure. This would allow a user who does not have access to a particular table to affect the behavior of how queries run, potentially causing queries to run slower than intended since metadata is removed from the cache. Although metadata will be cached again after querying a table, the procedure can potentially be abused.

It would be ideal if the procedure can check whether the user calling the procedure has write access to the table that metadata is being flushed for. Calling this procedure is generally related to ETL processes, which could be writing or replacing data for a table or partition, and then calling the procedure to ensure that new table or partition locations are picked up.

What's not clear would be what the appropriate privileges would be for calling the procedure with no arguments, i.e. clearing cached metadata for any table or schema.
