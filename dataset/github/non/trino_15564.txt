Hudi Connector performance issues while querying partitioned tables
Our team is testing the Hudi Connector on COPY ON WRITE HUDI tables. And we observed that the hudi connector in general performs poorly while querying partitioned tables, with or without metadata enabled. The query supposedly takes time in the state of `Creating InMemory based view for basePath`. Through the coordinator logs we see that query takes 1-2 mins after loading the metadata table to load the file system views using `AbstractTableFileSystemView`.

From seeing the explain plan of the query on Trino we could see that there were no specific filters on the partition column despite providing specific partition column values. Whereas if we do the same through the hive connector then it returns the specified values in the explain plan itself.

**Query:**
```
SELECT id 
FROM hudi.<schema_name>.<table_name>
WHERE insert_ds_ist in ('2022-12-12', '2022-12-11', '2022-12-01', '2022-12-02', '2022-12-03') 
LIMIT 12
```
