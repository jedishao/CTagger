Consolidate System and User Memory
I propose removing the distinction between user and system memory.  I don't think distinguishing the two is providing much value and it adds complexity that creates more room for error.

1. The user and system memory distinction makes our memory reservation process much more complex than it needs to be (e.g. see [https://github.com/.../presto/memory/QueryContext.java...](https://github.com/prestodb/presto/blob/eff77883d0d24dc6022ecde252612d1430c9fbac/presto-main/src/main/java/com/facebook/presto/memory/QueryContext.java#L215-L231)). The added complexity makes it harder to get to the bottom of issues or make changes related to memory accounting.
2. Most users (and many developers) don't know the difference between user and system memory.
3. Even if they did, there isn't a great reason to set different memory limits for user vs. system memory since at the end of the day your machine only has a certain amount of memory available and it doesn't care if that memory is being used by a partial aggregation or a final aggregation.
4. It's very easy to misconfigure clusters by not setting the total memory limit since many people don't realize that query.max-memory-per-node is only max *user* memory.


Consolidating these two memory types and removing the user memory specific limit would be a significant change to our memory enforcement, so I'd love to hear what others think.
