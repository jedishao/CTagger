Support for TLS "clientAuth" option based on server SNI hostname
In browser environment, it's useful to have a dedicated domain for TLS certificate authentication (eg. https://login.microsoftonline.com vs https://certauth.login.microsoftonline.com).

There is currently no support for setting "clientAuth" option in HttpServer based on SNI hostname so the beforementioned scenario can only be implemented with separate TCP port or IP address.

It would be great to have "clientAuth" SNI support similar to keyManagerMapper() in KeyCertOptions or some other method to "tap" into configureEngine() in SslHelper.
