I am seeking to be notified if there is a way to detect if a redisson cluster topology has changed, for example due to a failover of a redis master node in a shared (cluster deployment, current deployment is in AWS elasticache).

We have some use cases where we could like to flush our local caches only, in the case that there was a situation that the master of a shard failed, and a slave had some replication lag and data was lost.  So the scenario is:

1. High volume of changes to redis master
2. redis async replica slave receives data, but has a non-trivial replication lag 
3. master dies, before all data is replicated to slave
4. Slave is promoted to new master, but could be missing data due to replication lag

If this happens, we would like to be able to detect the topology change and flush our caches, to trigger server to reload data from database.

I see there is ```Config.setConnectionListener()```, and we have experimented with this.  However it only gives an inetaddress, and no indication of if the connection is to master or slave nodes, neither if it is due to any form of "connection pool cleanup" versus a cluster topology change.  We are also seeing this get called sometimes 5 minutes into establishing a redisson client and successfully interacting with elasticache via redisson.

Questions on this:
1. Does this connection listener get called during normal connection pooling (for example, if redisson has connection pool and it is refreshing connections in the pool as part of its normal operations)?
2. Is there any way to register for notifications of a cluster topology change, or perhaps if a node is changed from a slave to a master?
