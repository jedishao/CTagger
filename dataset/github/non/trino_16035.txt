Trino-jmx missing some metrics
I am using trino 359 and I found that some metrics is missing in `jmx.history` after the trino jmx catalog initialization, the same problem occurs with trino 407. The missing metrics are the metrics of some trino plugins.

I found that the reason for this is that the jmx catalog is instantiated before the other catalogs are instantiated. When the jmx catalog is instantiated, `JmxHistoricalData` queries the MBeans on the jmx server and filters the MBeans with the jmx.dump-tables configured in the configuration file, but if the other catalogs are instantiated after that time, `JmxHistoricalData` does not query the MBeans of the other catalogs. `JmxHistoricalData` can't query the mbeans of other catalogs, and eventually `jmx.history` will lose some tables. But we can find the corresponding table in `jmx.current`.

Since we have no way to control the order of instantiation of the catalog, I think we need to allow the jmx catalog to refresh the data in `JmxHistoricalData`.


Here is my case:
I had added `trino.plugin.hive.metastore.thrift:type=ThriftHiveMetastore,name=hive` in my jmx.properties, but I can not find it in `jmx.history`.
```properties
connector.name=jmx
jmx.dump-tables=trino.plugin.hive.metastore.thrift:type=ThriftHiveMetastore\\,name=hive,java.lang:type=Runtime,trino.execution.scheduler:name=NodeScheduler
jmx.dump-period=10s
jmx.max-entries=86400

```
