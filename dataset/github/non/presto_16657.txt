Avoid unnecessary data shuffle to add support for partition properties propogation
Presto optimizer does not propagate partition properties for joins using equi-join criteria. That is, optimizer chooses to repartition data on grouping key disregard if the grouping set matches with the join key which means the final aggregate of the groupby is already partitioned by the subsequent join.
```
SELECT count(*) 
FROM nation x, customer y 
WHERE x.regionkey = y.nationkey 
GROUP BY x.regionkey
;
```
