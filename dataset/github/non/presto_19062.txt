Decimal sum aggregate returns overflow error instead of result
Once the result overflows, the result is always an overflow error until there is an underflow.

```
presto> SELECT sum(c0) from (values DECIMAL '99999999999999999999999999999999999999', DECIMAL '99999999999999999999999999999999999999', DECIMAL '-99999999999999999999999999999999999999') t(c0);

Query 20230213_002729_00003_24nx5 failed: Decimal overflow

presto> SELECT sum(c0) from (values DECIMAL '99999999999999999999999999999999999999', DECIMAL '99999999999999999999999999999999999999', DECIMAL '-99999999999999999999999999999999999999', DECIMAL '-99999999999999999999999999999999999999') t(c0);
 _col0 
-------
 0     
(1 row)
```

The final evaluation must consider both the overflow count and the sum value.
See https://github.com/prestodb/presto/blob/36858f235283e7c16ae4ad4ce493bd80876b179b/presto-main/src/main/java/com/facebook/presto/operator/aggregation/DecimalSumAggregation.java#L187
