Iceberg REST catalog silently ignores 'location' schema and table property
When using the REST catalog with the iceberg connector, the location property is ignored when passed to `CREATE SCHEMA/CREATE TABLE`. 

Instead, the bucket location associated with the warehouse `iceberg.rest-catalog.warehouse` is always utilized. 

This was confusing, probably better is explicitly erroring out when attempting to use the `location` property with the iceberg REST catalog instead of silently ignoring the property.  

Example:
```
trino> create schema iceberg.grant_test with (location='s3://bucketnamehere/');
CREATE SCHEMA
trino> show create schema iceberg.grant_test;
                                    Create Schema                                     
--------------------------------------------------------------------------------------
 CREATE SCHEMA iceberg.grant_test                                                     
 WITH (                                                                               
    location = 's3://warehousebucketlocation/cd0c8e4f-76d5-44e6-b098-94a5a82c4b4b/' 
 )                                                                                    
(1 row)
```
