Improve Projections
Projections was one of the top contributor to memory allocations that causes full GCs and OOMs. It also has space to improve in terms of CPU usage. We propose the following changes to optimize projections:

Pre-allocate enough memory 

  - Part one was implemented in https://github.com/prestodb/presto/pull/15206 which brings 33% improvement in projection's throughput (higher is better) and 4x reduction in gc.alloc.rate.norm (lower is better) in GC benchmarks.

  - Part two will be additionally avoiding unnecessary growCapacity for nested types.

Optimize BlockBuilder element insertions
  - Currently each writeXXX go through several checks for each value. Some checks can be omitted.
  - getBlock() takes high CPU usage because it's called on each value. This is totally unnecessary.
  - isNull() takes high CPU usage. For blocks that can't have nulls this is totally unnecessary.

Create DictionaryBlock for identity projections
  - Currently blocks are copied. Building DictionaryBlock would be much faster
  - Then we probably need to disable MergingPageOutput before repartitioning because repartitioning would flatten the DictionaryBlock.
