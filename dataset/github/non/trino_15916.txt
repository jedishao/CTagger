Top-N query on the pinot connector does not support Top-N pushdown functionality
We are running the Top-N pinot query from trino (The combination of a LIMIT-N with an ORDER BY clause). The limit-N looks not be pushed down into pinot, the query is slow and also cased the Pinot high I/O issue in this case.

Based on Query Plan, the Top-N operation TopN is being applied in the Fragment 1 by Trino and not by the source database. In Fragment 2(source) pinot looks scan large dataset and transferred large amount of data to Trino without limit in TableScan.

BTW: no any issue if run same query in pinot direclty(fast and no high I/O in pinot).

#Query
SELECT callstarttime , callingnumber , countrycode ,callingid , durationsecs  
FROM call WHERE id in ('xxxx') AND to_unixtime(date('2022-01-31'))/86400 <= callstarttimedays and callstarttimedays <= to_unixtime(date('2023-01-30'))/86400 
ORDER BY callstarttime DESC  limit 10
