DruidLeaderClient.goAsync() is broken
### Affected Version

0.18.0

### Description

This bug seems to be introduced after https://github.com/apache/druid/pull/9481. Before this PR, `DruidLeaderClient` used to use `ServerDiscoverySelector` to find the leader. Since only the leader Overlord and Coordinator announce themselves, `ServerDiscoverySelector` could return the current leader to `DruidLeaderClient`. But now, `DruidLeaderClient` picks up the first node returned from `DruidNodeDiscovery` which knows all announced nodes. Since `DruidLeaderClient.goAsync()` doesn't follow redirection (https://github.com/apache/druid/issues/8716), some methods of the system table which use `goAsync()` API returns an error with the Temporary Redirect status.
