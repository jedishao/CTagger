deconstruct_tdigest returns centroid_weights as integers, which can result in inaccurate weights for digests of a large number of elements
I noticed for some large tdigests, the sum of centroid weights did not match the count returned by deconstruct_digest, I suspect because deconstruct_tdigest returns the count as a bigint but the centroid weights as integers:

https://github.com/prestodb/presto/blob/36858f235283e7c16ae4ad4ce493bd80876b179b/presto-main/src/main/java/com/facebook/presto/operator/scalar/TDigestFunctions.java#L44-L52

Without accurate centroid weights it's impossible to reconstruct the tdigest accurately from the outputs of deconstruct_tdigest.
