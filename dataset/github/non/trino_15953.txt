Persisting Trino Query Logs
Currently the Trino query logs are only persisted in memory on the Coordinator and are lost once newer queries run. Our team is working on persisting query logs to long term storage and will create a custom endpoint to read from storage if the log isn’t available in memory. This endpoint will be used by the Trino UI if the log isn’t available at `ui/api/query/<query_id>`

The `queryCompletedEvent` method in the `QueryMonitor` class can access the full `QueryInfo` from `LocalDispatchQuery`, but the `queryCompletedEvent` method in `QueryMonitor` isn’t emitting the full log (which is required if we want to be able to visualize historical data). The `queryInfo` object isn’t available from the `event` or `spi` packages.

We have determined some approaches to solve for this:
- Create a custom query monitor in the `event` package
- Add a new event in `eventListenerManager` that will read the full query log
- Pass the full `queryInfo` object into the `QueryCompletedEvent` as a new parameter
- Use the `v1` API to pull the full queryInfo

It seems like regardless of the approach we choose (except using the API endpoint), we will probably need to build a new object in the `spi` package for the `QueryInfo` object we are passing. If there is interest, we would like to make this change upstream, since this is likely a common issue. Do you have any advice on the approach (any of the ones above or one we haven’t considered) that would be best for storing the full query log output?
