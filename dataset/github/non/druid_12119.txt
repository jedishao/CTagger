Inconsistent behavior on using week level granularities when it comes to start of returned timestamps
The returned timestamps on using P1W and P2W should have been the same (Monday of the first week) when not using origin.


### Affected Version

0.18.1

### Description

When we use P1W granularity, the returned timestamp starts from the Monday of the same week as the queried interval, and that is as documented. So when queried interval starts on Nov 4 2020 (Wed), response timestamp starts on Nov 2 2020 (Monday).
However, with the same interval, if we just change granularity to P2W or anything other than P1W, the response timestamp starts on the Thursday of the previous week (Oct 29 2020)

- Cluster size : Single VM single replica deployment. VM size 64 core CPU with 256 GB RAM
- 
- Steps to reproduce the problem : Use group by query with first P1W and then with P2W or higher week counts but without specifying the origin explicitly. The returned timestamps are expected to start from Monday of that first week and that is the case for P1W but not for P2W.
