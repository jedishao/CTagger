After failover redisson attempts to connect to the failed master indefinitely
<!--
Try Redisson PRO https://redisson.pro with ultra-fast performance and support by SLA.
-->

**Expected behavior**
When a new master is elected in the cluster, redisson should realize this and remove the old clients from the connection manager.

**Actual behavior**
After failover, when new master is elected redisson still tries to create connections to the failed, previous master.
Even if ReadMode and SubscriptionMode is set to Master.

**Steps to reproduce or test case**
Setup a redis cluster with replica nodes. Connect with redisson client. Do failover.
**Redis version**
6.2.7
**Redisson version**
3.17.7
**Redisson configuration**
```java
        Config config = new Config();
        config
                .useClusterServers()
                .addNodeAddress("redis://127.0.0.1:7000")
                .addNodeAddress("redis://127.0.0.1:7001")
                .addNodeAddress("redis://127.0.0.1:7002")
                .addNodeAddress("redis://127.0.0.1:7003")
                .addNodeAddress("redis://127.0.0.1:7004")
                .addNodeAddress("redis://127.0.0.1:7005")
                .setReadMode(ReadMode.MASTER)
                .setSubscriptionMode(SubscriptionMode.MASTER)
                .setRetryAttempts(30)
                .setRetryInterval(1500);
```

I've captured the redisson debug logs, and searched for the cluster nodes command. You can see below, that all neccessary information is available to change the master. I realized, there is a function that should do this in `ClusterConnectionManager::changeMaster`. I put a breakpoint there, but it is never called. I think `ClusterConnectionManager::checkMasterNodesChange` should do this, but it's too complex for me to localize the problem.
