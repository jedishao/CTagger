Support for Azure Managed Identity authentication for ABFS
[Managed (Service) Identities](https://learn.microsoft.com/en-us/azure/active-directory/managed-identities-azure-resources/overview) are a secret-less means of authenticating between Azure services. Using MSI is an alternative to injecting an oauth secret into an Azure resource (e.g. a Kubernetes pod). I think it would be both useful and easy for Trino to support this authentication model.

I am saying this would be easy because:
- Hadoop-azure [already supports](https://hadoop.apache.org/docs/stable/hadoop-azure/abfs.html#Azure_Managed_Identity) managed identities, via the `org.apache.hadoop.fs.azurebfs.oauth2.MsiTokenProvider` provider class.
- it seems like all Trino would have to do is change the fields initialized in [TrinoAzureConfigurationInitializer](https://github.com/trinodb/trino/blob/6310e5e1415fe0bc89444016fc516640c3a3fcbb/plugin/trino-hive/src/main/java/io/trino/plugin/hive/azure/TrinoAzureConfigurationInitializer.java#L103) to support this authentication model.

This would also be useful because:
- managed identities are a core IAM construct on Azure, so this would improve Trino's overall security footprint across that cloud product.
- managed identities can be a first step towards implementing IAM for Trino via [workload identity](https://blog.baeke.info/2022/11/24/aks-workload-identity-revisited/) on Azure Kubernetes Service. Specifically, it seems like MSI authentication could help support workload identity via the [migration sidecar solution](https://learn.microsoft.com/en-us/azure/aks/workload-identity-migrate-from-pod-identity#deploy-the-workload-with-migration-sidecar) offered by Microsoft.

I am not super familiar with the Trino development process, but given that this feature should require only a few config changes to be passed to `hadoop-azure`, I am happy to volunteer to implement this myself, although it would be even nicer if this made it onto some roadmap :)
