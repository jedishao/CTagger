[Spilling] Reduce memory pressure during unspill-and-merge-sort stage for large groups
Creating an issue to track the unspill-merge-sort improvements discussed during the review of this PR [18400](https://github.com/prestodb/presto/pull/18400)
This affects HashAggregationOperator, TopN*Operator  WindowOperator and OrderByOperator

We found out that, in particular cases, the Unspilling of pages and merge sorting them produces more memory pressure than the case where we didn't spill at all. We should consider fixing the merge sort code for these scenarios.

Scenario: 
Let's consider that under high memory pressure, revoke is triggered multiple times during input collecting phase of the operator. 
Let us also consider that it is possible that within this input there is a group that has disproportionately large record count. This large group will be present (in its intermediate representation form) in many/all of the spill pages. 

Now during unspill/output, we will read this data few-groups-at-a-time, by copying the merge sorted group rows into a new intermediate page, before passing it for final reduce/computation. This intermediate page creation is based on the condition that it is atleast as large as `PageBuilderStatus.DEFAULT_MAX_PAGE_SIZE_IN_BYTES` and also full contains all the groups.  
This is implemented by the function
```
MergeHashSort.keepSameHashValuesWithinSinglePage() 
```

This means that when we encounter the said large group in this process, the intermediate page will HAVE TO contain ALL the rows of this group in this single page in memory. So effectively, we have created more memory pressure than if we had not spilled at all.

Possible Solutions
1. Instead of MergeSort producing fully contained groups, it can produces pages with non-fully contained group along with metadata of wether the last group in the page is fully contained. The downstream builder (SpillableHashAgg, SpillableGroupedTopN, SpillablePagesToPagesIndexes) can use this metadata to decide when to flush. 

3. Remove the intermediate Page builder and directly pass the output of merge sort to the consumers
