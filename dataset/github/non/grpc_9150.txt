Upgrading to grpc 1.45.0 from 1.40.1 causes too much time for the server to start
### What version of gRPC and what language are you using?
Upgraded to 1.45.0 from 1.40.1. 
Java/Kotlin


### What operating system (Linux, Windows,...) and version?
Linux


### What runtime / compiler are you using (e.g. python version or version of gcc)


### What did you do?
We upgraded our grpc version from 1.40.1 to 1.45.0

### What did you expect to see?
Our server starts in approximately 2 minutes after grpc 1.45.0 upgrade without any exceptions.


### What did you see instead?
After upgrade, it takes more than 3 minutes for some pods to start and eventually tries restarting multiple times and ends up in backoff state. This also happens with our liveliness probe eventually causing our apps to get restarted in PROD.

Also getting BouncyCastle ALPN class not found exception. This error did not occur with 1.40.1 version.

Reverting back to 1.40.1 solves the problem in lower environment.
