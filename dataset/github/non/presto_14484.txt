Hive bucket pattern is not identical with Hive implementation 
Current regex [pattern](https://github.com/prestosql/presto/blob/43b55cba71bc7345977f292f91b1a082ada72fdf/presto-hive/src/main/java/io/prestosql/plugin/hive/BackgroundHiveSplitLoader.java#L112) in Hive connector is 

`Pattern.compile("(0\\d+)_\\d+.*")`

 while the pattern in [Hive implementation](https://github.com/apache/hive/blob/master/ql/src/java/org/apache/hadoop/hive/ql/exec/Utilities.java#L1255) is 

`Pattern.compile("^(0*([0-9]+))_([0-9]+).*")`

These 2 are not identical, e.g. `100001_1` is qualified for the pattern in Hive implementation while it's not qualified for the pattern in presto-hive since it requires the bucket prefix to be started with `0`.

~Also if we decided to support/allow any number of files per bucket, including zero, should we consider to add a config item to the use to further allow them to control whether the bucket file number check is needed, and set the default value to `false` for backward compatibility.~

~I ran an insert overwrite query on `Hive 2.3.4 + Tez 0.8.4` to insert data into a table which has bucket number set to `4`, only one file got generated (inserted only few rows for testing) and the generated file is named in `000003`...without an option to skip the file number check, I couldn't run my Presto query on top of this partition even after I upgrade my Presto to 317~
