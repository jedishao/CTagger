Inconsistent handling of null input in cardinality(approx_set()) vs. approx_distinct
Intuitively, one would expect cardinality(approx_set(x)) to return same result as approx_distinct(x). However, we are seeing that is not always the case. Here is an example,

```
presto> select approx_distinct(x), cardinality(approx_set(null)), count(distinct (x)) from (values (null)) as t(x);

 _col0 | _col1 | _col2
-------+-------+-------
     0 | NULL  |     0
(1 row)
You sent
```
