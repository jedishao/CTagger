MySQL case-sensitive table names inconsistent behaviour
We have upgraded Trino from 367 to 409 and some queries started failing. 
Minified example of failing query:
```sql
SELECT * 
FROM mysql.bd.daily_updating_table 
WHERE srole in (
  SELECT srole
    FROM mysql.bd.daily_updating_table
    WHERE 1=1
      and aid = '11938123193023'
      and day_of_change = current_date - interval '3' day
);
```

This one doesn't work as well
```sql
SELECT * 
FROM mysql.bd."DAILY_Updating_Table" 
WHERE srole in (
  SELECT srole
    FROM mysql.bd."DAILY_Updating_Table"
    WHERE 1=1
      and aid = '11938123193023'
      and day_of_change = current_date - interval '3' day
);
```

But simpler queries work fine, e.g.:
This works fine:
```sql
SELECT * 
FROM mysql.bd.daily_updating_table 
WHERE srole in (
  SELECT srole
    FROM mysql.bd.daily_updating_table
    WHERE 1=1
      -- and aid = '11938123193023'
      and day_of_change = current_date - interval '3' day
);
```
This works fine too:
```sql
-- SELECT * 
-- FROM mysql.bd.daily_updating_table 
-- WHERE srole in (
  SELECT srole
    FROM mysql.bd.daily_updating_table
    WHERE 1=1
      and aid = '11938123193023'
      and day_of_change = current_date - interval '3' day
-- );
```
And this is also fine:
```sql
  SELECT * FROM mysql.bd.daily_updating_table LIMIT 1
```

We didn't set config `case-insensitive-name-matching` so default value is `false`. When I changed it to `case-insensitive-name-matching=true` nothing has changed, it still fails. 
And it's interesting that the query works fine on old Trino 367 without the config.

I know that case-sentive support now is limited and we probably don't need it right now, it would be enough to have `case-insensitive-name-matching=true` working.
