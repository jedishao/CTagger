API > The create cluster request returns 204 even if the body is not specified
### Search before asking

- [X] I searched in the [issues](https://github.com/apache/pulsar/issues) and found nothing similar.


### Version

**Pulsar version** : 2.9.2
**OS**: CentOS Linux release 7.9.2009 (Core)


### Minimal reproduce step

The problem occurs when you run the create cluster request without specifying the body. For example:

```
curl -X PUT  http://host:9372/admin/v2/clusters/examplecluster
```
In the documentation (https://pulsar.apache.org/admin-rest-api/#operation/createCluster), the only required parameter is the cluster name. But checking in the code you can see that the body is also required.


### What did you expect to see?

I expect that since the body is required the API returns me an error.

### What did you see instead?

Instead the api returns me 204.
However, if I try to get that cluster, I get an error:
```
[apache-pulsar-2.9.2]$ curl http://host:9372/admin/v2/clusters/examplecluster
{"reason":"Cluster does not exist"}
```

But if I check the list of available clusters... The cluster I tried to create is also in the cluster list.

```
curl http://host:9372/admin/v2/clusters/
["magnews","examplecluster"]
```


### Anything else?

To solve the problem I passed an empty body to the request.
Something like:
```
curl -H 'Content-Type: application/json' -X PUT -d '{  }' http://host:9372/admin/v2/clusters/examplecluster
```
In this case I have seen that the cluster is created correctly with the default values.
```
 curl http://host:9372/admin/v2/clusters/examplecluster
{"brokerClientTlsEnabled":false,"tlsAllowInsecureConnection":false,"brokerClientTlsEnabledWithKeyStore":false,"brokerClientTlsTrustStoreType":"JKS"}
```
