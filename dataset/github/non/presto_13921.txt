Provide optional cache for Parquet file metadata
Similar to the ORC changes that introduce metadata caching in https://github.com/prestodb/presto/pull/13501 and https://github.com/prestodb/presto/pull/13575 it would be beneficial to provide this mechanism for Parquet files as well to potentially avoid 2 extra reads per file (tail read for metadata length + actual metadata read) and avoid remote reads completely in subsequent executions where min/max stats can rule out the file immediately.
