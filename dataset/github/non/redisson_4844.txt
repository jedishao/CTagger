AWS Lambda throwing RedisNodeNotFoundExceptions
**Expected behavior**
* Lambda should be working fine without throwing any `RedisNodeNotFoundException`.

**Actual behavior**
* Getting around 8-10% `RedisNodeNotFoundException` errors. 
One example log:- 
```
Caused by: org.redisson.client.RedisNodeNotFoundException: Node for slot: 12434 hasn't been discovered yet. Check cluster slots coverage using CLUSTER NODES command. Increase value of retryAttempts and/or retryInterval settings.
at org.redisson.connection.MasterSlaveConnectionManager.createNodeNotFoundException(MasterSlaveConnectionManager.java:562)
at org.redisson.command.BaseRedisBatchExecutor.getEntry(BaseRedisBatchExecutor.java:81)
at org.redisson.command.BaseRedisBatchExecutor.addBatchCommandData(BaseRedisBatchExecutor.java:89)
at org.redisson.command.RedisBatchExecutor.execute(RedisBatchExecutor.java:53)
at org.redisson.command.CommandBatchService.async(CommandBatchService.java:162)
at org.redisson.command.CommandAsyncService.writeAsync(CommandAsyncService.java:490)
at org.redisson.RedissonObject.deleteAsync(RedissonObject.java:205)
```

**Steps to reproduce or test case**
1. We are working on AWS ElastiCache for Redis
2. Our cache cluster has 3 shards. Each shard has 1 master and 0 replication nodes.

**Issue Description**
* We enabled in-transit and rest encryption of our AWS Redis elasticache. After these changes we are seeing such errors.
* After caches were redeployed for encyption changes we were able to successfully hit APIs (hosted on Fargate) using this cache and saw reduced latency as well which indicated that cache is functional. But in our lambda we are seeing the following error. One unusual thing we noticed in our logs is that there are many slave reconnections within a very short span of time:-
```
[INFO] (redisson-netty-5-9) org.redisson.cluster.ClusterConnectionManager: slave: rediss://10.0.97.77:6379 added for slot ranges: [[0-16383]]
```
Which didn't used to happen before these changes. Also we upgraded redisson from 3.16.x to 3.18.0 as we were having issues while calling our APIs which got resolved after using 3.18.0. Both lambda and API service uses this common redisson client package.
* We also saw that these errors got resolved for clients after upgrading from redisson 3.16.x to 3.17.x/3.18.x but not for us apparently.
*  This error is retry-able. It gets resolved after retrying the request after few times. To me it looks like some lambda + redisson issue based in these facts.

**Redis Engine version**
6.2.6
**Redisson version**
3.18.0

**Redisson configuration**
```
public RedissonClient getRedissonProfileCacheClient(final ObjectMapper objectMapper,
                                                        @Named("domain") final String domain) {
        String redisUrl = ResourceConfig.PROFILE_CACHE_CLUSTER_CONFIG_MAP.get(domain);
        Config config = new Config();
        // Codec for json <-> java object serialization/deserialization
        config.setCodec(new JsonJacksonCodec(objectMapper));

        // Only one node of cluster configuration endpoint need to be specified - all other nodes are auto detected
        // Reference for configuration parameters
        // https://github.com/redisson/redisson/wiki/2.-Configuration
        config.useClusterServers()
                .setReadMode(MASTER_SLAVE)
                .setCheckSlotsCoverage(false)
                .addNodeAddress(redisUrl)
                .setTimeout(REDIS_TIMEOUT)
                .setRetryAttempts(REDIS_RETRY_ATTEMPT)
                .setRetryInterval(REDIS_RETRY_INTERVAL)
                .setConnectTimeout(REDIS_CONNECTION_TIMEOUT);

        return Redisson.create(config);
    }
```
