PrestoS3FileSystem.delete swallows errors in recursive mode
The error handling of `PrestoS3FileSystem.delete` (see [PrestoS3FileSystem:492](https://github.com/prestodb/presto/blob/master/presto-hive/src/main/java/com/facebook/presto/hive/s3/PrestoS3FileSystem.java#L492)) seems to be broken if called with the `recursive` flag enabled. It will try to delete directory content but doesn't check for errors "reported" through the return value. As a consequence, the `delete` call will return `true` even if the objects with the given path were not deleted.

The same issue is observed for [TrinioDB issue #11352](https://github.com/trinodb/trino/issues/11352)
