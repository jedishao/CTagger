Add AuthenticationFilter to check principal of internal communications
Today, we apply same `AuthenticationFilter` to internal/external communication. However, we don't check who is allowed to access the server. For external communications, this is controlled later by `AccessControlManager`.  However, it is very easy if someone obtained a valid certificate to send HTTPS request to internal communication end points and get sensitive informations.

We should use separate `AuthenticationFilter` for internal/external communication. One idea is to mark external communication endpoints with annotation using JAX-RS name binding:
https://javaee.github.io/javaee-spec/javadocs/javax/ws/rs/NameBinding.html

For internal communications, we should allow only the principal contained in the server certificate.
