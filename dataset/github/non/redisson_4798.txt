**Is your feature request related to a problem? Please describe.**
We are using redisson for our distributed lock. We were seeing issues with unlock latency jumping to more than 1000 ms when we do live cluster configuration where replicas were brought down and up. After reading the code, I saw that this is due to a wait command being issued so that it only returns after 1 second timeout or all replicas of the master were synced. Form what I understand, the purpose of syncing with replicas is to increase consistency? However, this is not ideal for our use cases. 

**Describe the solution you'd like**
Can we make the sync slaves number of replicas and timeout configurable? 
`        BatchOptions options = BatchOptions.defaults()
                                            .syncSlaves(availableSlaves, 1, TimeUnit.SECONDS);`
