Implement a new mechanism to expose metrics from operators and connectors
Most of the functionality has been implemented. I am creating this issue to track the related PRs and design doc.

In the previous metric tracking mechanism, adding a new operator metric requires lots of manually work such as 

- adding a specific variable, 
- updating the aggregation logic at different levels, 
- updating the presto cli and coordinator web UI to show the metrics, 
- update the event listeners to log it to scuba/hive/manifold as an individual column.

This new metric tracking mechanism uses a map to track the metrics values and use string to represent arbitrary metric names. So adding a new metric is a one-line change.

Design doc: https://docs.google.com/document/d/1M1LVUMoaKAwt22bLTP6o-SAhX8rahhTwP0SzC-L29VU/edit#
