Deprecate fault-tolerant-execution-max-task-split-count
With https://github.com/trinodb/trino/pull/16719, we are getting smarter around packing task splits, and we are intentionally controlling the number of tasks per stage. With 50GB max size, 64MB standard split size, we can pack 800 splits per tasks, and the max task split count looks redundant now. It would be ideal to get rid of it. 

However, we need to make sure that splits are assigned to workers incrementally, so we don't run into something like JSON request size exceeded.
