"No route to host" to hdfs arised in k8s after some time's normally running
I deployed the druid in k8s, using hdfs as deep-storage by mounting the core-site.xml and hdfs-site.xml into the class path of the pod.

Everything worked well, but after a long term(don't known the condition right now), the historical node and middle-manager node just counld't get connected to the hdfs. The logs show: "No route to host".

### Affected Version

0.20.0

### Description

Below is logs from one of the historical node pod

[kdl-druid-historical-10.log](https://github.com/apache/druid/files/6432744/kdl-druid-historical-10.log)

### Investigation

1. jvm's version is 1.8, so java negative DNS caching problem can't be blamed described in [hadoop wiki](https://cwiki.apache.org/confluence/display/HADOOP2/NoRouteToHost).

2. traceroute:
