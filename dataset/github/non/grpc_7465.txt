What is the correct Kubernetes health status for channel state TRANSIENT_FAILURE?
The [Javadoc](https://grpc.github.io/grpc-java/javadoc/io/grpc/ConnectivityState.html#TRANSIENT_FAILURE) states:

> Channels in this state will eventually switch to the CONNECTING state and try to establish a connection again.

Which of [Kubernetes liveness and readiness check](https://kubernetes.io/docs/tasks/configure-pod-container/configure-liveness-readiness-startup-probes/) does this map to? I believe the application is alive but not accepting requests, not down, but I can see someone arguing the other way.
