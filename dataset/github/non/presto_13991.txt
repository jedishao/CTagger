like_pattern row expression interpretation errors out on SERIALIZABLE optimization level
Can be reproduced with tpch query. It was not an issue in 0.228
```sql
SELECT
    *
FROM (
    SELECT
        name,
        comment
    FROM customer
    WHERE
        name NOT LIKE 'test_|%' ESCAPE '|'
        AND name = 'di'
) a
JOIN (
    SELECT
        shipmode,
        comment
    FROM lineitem
) b
    ON a.name = b.shipmode
```
