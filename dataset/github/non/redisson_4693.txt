**Expected behavior**
- if an exception (RedissTImeoutException, RedisResponseTimeoutException) occurs, not misread data from the buffer.
- When an error occurs, in the [syntax below](https://github.com/redisson/redisson/blob/4d3ae58f0e81924a79f943d764daaff549884308/redisson/src/main/java/org/redisson/client/handler/CommandDecoder.java#L107), it is necessary to distinguish whether data is in the buffer or not.
```
// org.redisson.client.handler.CommandDecoder.java#L107
if (data.isExecuted()) {
    in.readerIndex(endIndex);
    sendNext(ctx.channel());
    return;
}
```

**Actual behavior**
- Even if there is no data, `in.readerIndex(endIndex)` is executed and the index is skipped.
- So, in the case of a GET command, the response of another command (ex. PSETEX) is read and `ClassCastException` occurs.

**Steps to reproduce or test case**
- Calls to read the 2nd level entity repeatedly. (GET Command)
- This is more likely to happen if you shorten the `timeout` or `retryInterval` or entity TTL setting.

**Redis version**
- 7.0.5

**Redisson version**
- 3.18.0
