NPE when NetSocket.upgradeToSsl() is called if no TLS configuration in NetClientOptions
### Version

4.3.4-SNAPSHOT

### Context

When there is no TLS related configuration specified in the NetClientOptions, and user tries to call `NetSocket.upgradeToSsl(handler)`, the handler will not be called because of NPE was thrown.


This also leads to some CI failures in other components, like: 

* https://github.com/vert-x3/vertx-auth/actions/runs/3057964143/jobs/4933654463
* https://github.com/vert-x3/vertx-mail-client/actions/runs/3057975832/jobs/4933678374

The `sslProvider` in SSLHelper may be `Future.succeededFuture()` which will make `Supplier<SslContextFactory>` is null, so nothing to supply the `SslContextFactory` in this case. I think we need to decide what to do in this case.

https://github.com/eclipse-vertx/vert.x/blob/e3100d67bcbe85665f7147bcc48ce6a4720367db/src/main/java/io/vertx/core/net/impl/SSLHelper.java#L196-L225

### Do you have a reproducer?

The following test hangs and fails:

```java
  /**
   * Test that NetSocket.upgradeToSsl() should fail the handler if no TLS configuration was set.
   */
  @Test
  public void testUpgradeToSSLIncorrectClientOptions() {
    server.close();
    server = vertx.createNetServer(new NetServerOptions().setSsl(true).setPort(4043)
      .setKeyCertOptions(Cert.SERVER_JKS_ROOT_CA.get()));
    NetClient client = vertx.createNetClient();
    server.connectHandler(ns -> {}).listen(onSuccess(v -> {
      client.connect(4043, "127.0.0.1", onSuccess(ns -> {
        ns.upgradeToSsl(onFailure(err -> client.close(onSuccess(s -> testComplete()))));
      }));
    }));
    await();
  }
```
