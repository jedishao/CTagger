gRPC clients always send grpc-accept-encoding header as Gzip
I noticed that the gRPC Java clients always send `grpc-accept-encoding=gzip` whether I enabled Gzip compression or not. Is this the intended behaviour?.

AFAIU, the reason for this behaviour is `DEFAULT_INSTANCE` of the `CompressorRegistry` is using `Gzip` as the first parameter.

https://github.com/grpc/grpc-java/blob/e4a13778e00aa03d1a9ee5cd2cfd6023d1b4f778/api/src/main/java/io/grpc/CompressorRegistry.java#L33

I couldn’t find such a statement in the gRPC compression [spec](https://github.com/grpc/grpc/blob/master/doc/compression.md). Moreover, the gRPC Go language clients don't do such a thing.
