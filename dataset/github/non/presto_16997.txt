Scheduler does not schedule the tasks to all workers for small dataset for SOFT_AFFINITY
Some Ahana's customers run small clusters with 2 - 4 nodes and they have small dataset too. We observed the tasks were not scheduled on all worker nodes sometimes and this caused uneven distribution of the work and causing query elapsed time not meeting SLA. 

We were able to reproduce this using HiveQueryRunner. This pic shows the tasks on a 3 node cluster with hive.node_selection_strategy set to be NO_PREFERENCE.

WIth SOFT_AFFINITY, only 2 nodes were selected:
<img width="1186" alt="WITH_SOFT_AFFINITY" src="https://user-images.githubusercontent.com/33299678/141931543-b2331217-60b9-443a-893d-065d83cbfcf4.png">

Naveen has root caused the issue:

In case of SOFT_AFFINITY, the method HiveSplit::getPreferredNodes() method hashes the file path and gives out two nodes as preferred nodes(primary and secondary). In my test(5 worker nodes), I had 5 files in the table and so these file paths after hashing have only three worker nodes set as primary. Please see below the output of the code taken from this method executed separately for the file paths of my table.

PrimaryNode = 0 , SecondaryNode=1
PrimaryNode = 4 , SecondaryNode=0
PrimaryNode = 3 , SecondaryNode=4
PrimaryNode = 4 , SecondaryNode=0
PrimaryNode = 3 , SecondaryNode=4

Only nodes 0,3,4 are set as primary. Node 2 is never selected as primary or secondary and Node 1 is selected as Secondary once. After this, the SimpleNodeSelector::chooseLeastBusyNode() method has logic to choose the first preferred node(primary) if splits assigned to this node is less than maxSplitCount, which is true and we always end up choosing only Primary Node for all splits i.e 0,3,4, only three workers to process the splits instead of 5.
