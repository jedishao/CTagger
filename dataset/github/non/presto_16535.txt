Add a rule to rewrite AGG(IF()) to AGG() WITH FILTER
AGG(expr) FILTER (WHERE condition) is more efficient than AGG(IF(condition, expr)), because the former form has the following advantages: 
- the filter can be pushed down to the scan node 
- the rows not matching the condition are not aggregated
- the IF() expression wrapper is removed.

We observed 2.3X CPU reduction for some production queries by rewriting it manually. We could add a rule to do this rewrite automatically.
