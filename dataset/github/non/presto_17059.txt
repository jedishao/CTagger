selecting a view's column with a schema qualified name raises an exception
When working with a table, column names are allowed to be totally unqualified, qualified by a tablename, or qualified by a schema name and a table name 

For example
```sql
create table app.my_tab (one int);

select
	one,           -- works
	my_tab.one,    -- works
	app.my_tab.one -- works
from
	app.my_tab;
```

In contrast, when working with a view, qualifying names with a schema and a table name raises an exception

```sql
create view app.my_view as (select 1 as one);

select 
	one,            -- works
	my_view.one,    -- works
	app.my_view.one -- SQL Error
from
	app.my_view;
```

The exception raised is:
```
SQL Error [1]: Query failed (#20211202_163607_00080_hyxfa): line 1:8: Column 'app.my_view.one' cannot be resolved
```

The inconsistent handling is surprising and is an issue for ORMs that use schema qualification by default e.g. SQLAlchemy
