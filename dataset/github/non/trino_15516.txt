min/max aggregations have worse cpu performance with annotation functions
We found that when a simple sql used min()/max() functions in our production environment, the machine CPU load displayed in Grafana became very high.  

So we checked the source codes, and found that the annotation function features are introduced in trino 383: https://github.com/trinodb/trino/pull/11477  

Then we made a test, here are the steps:    
(1) make a tpch hive table `lineitem` with about 20GB data, the table schema is like this:  
```
show create table test.hivelineitem;
             Create Table              
---------------------------------------
 CREATE TABLE hive.test.hivelineitem ( 
    orderkey bigint,                   
    partkey bigint,                    
    suppkey bigint,                    
    linenumber integer,                
    quantity double,                   
    extendedprice double,              
    discount double,                   
    tax double,                        
    returnflag varchar(1),             
    linestatus varchar(1),             
    shipdate date,                     
    commitdate date,                   
    receiptdate date,                  
    shipinstruct varchar(25),          
    shipmode varchar(10),              
    comment varchar(44)                
 )                                     
 WITH (                                
    format = 'ORC'                     
 )
```

(2) The test SQL are simple, they are `explain analyze select min(extendedprice) from test.hivelineitem;` and `explain analyze select max(extendedprice) from test.hivelineitem;`. 
(3) We compared the CPU time in query plans between trino 380 and 392, and the results look like this:
