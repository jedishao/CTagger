Support intercepting queries that does not fulfill predefined rules
We'd like Presto to have the ability to define a set of rules that query must satisfy, otherwise fail the query directly. The scenario is that if someone who is not familiar with SQL/Presto, he would write a query like:

```sql
select * from very_big_tbl
```

if tbl is a very big table with tens of thousands of partitions, the single query might occupy all the resource of the cluster, so it would be good, if we can intercept this kind of behaviour.  Some sample rules might be:

* For partition table, SELECT statement must have a partition predicate and should query at most 10 partitons.
* If there is a order by, there should followed by a limit
