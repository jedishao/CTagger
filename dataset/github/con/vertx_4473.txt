HttpClient send multipart request can exhaust heap space
### Version

4.3.3

### Context

When using HttpClient from multiple event loops theads that all make a "send multipart" request to the same target, then it's possible to exhaust the heap memory.
This happens because the same `Connection` is used for all requests, which leads to requests coming from a different thread than the one attached to the connection being handled like this:

https://github.com/eclipse-vertx/vert.x/blob/4.3.3/src/main/java/io/vertx/core/http/impl/Http1xClientConnection.java#L517.

This in turn can cause the task queue of the event loop to pile up requests very quickly when the multipart requests contains a large file.

### Do you have a reproducer?

I have reproduced this in Quarkus using the Reactive REST Client which uses HttpClient under the hood. I can supply this reproducer or try and create a pure Vert.x one if needed.
