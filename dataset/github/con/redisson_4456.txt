MultiLock doesn't lock atomically/leaves locks in inconsistent state
**Expected behavior**
(Preferably) MultiLock locks atomically - either all locks are locked together, or none is locked. Alternatively, MultiLock should at least clean up after itself and unlock locks it erroneously got. If that isn't possible either - it should at least stop running the watchdog so locks expire at some point.

**Actual behavior**
Locks may be in different states after MultiLock acquisition gets interrupted

**Steps to reproduce or test case**
(excuse the Kotlin code)

```kotlin
suspend fun main(args: Array<String>) = coroutineScope {
    val rndLockName = Random.nextLong() // prevent different runs from interfering with each other
    val client = getClient()
    val lock1 = client.getSpinLock("testing$rndLockName")
    val lock2 = client.getSpinLock("testing2$rndLockName")
    val multi = client.getMultiLock(lock1, lock2)
    val job = async(start = CoroutineStart.ATOMIC) {
        val controlId = Random.nextLong()
        val gotLock = multi.tryLockAsync(20, -1, TimeUnit.SECONDS, controlId).toCompletableFuture().await()
        try {
            // mostly never reached anyways
            delay(1000)
        } finally {
            withContext(NonCancellable) {
                println("unlocking")
                try {
                    multi.unlockAsync(controlId).toCompletableFuture().await()
                } catch (e: Throwable) {
                    println("Ex $e")
                }
            }
        }
    }
    delay(1)
    job.cancelAndJoin()
    println(
        "IsLocked ${lock1.isLockedAsync.toCompletableFuture().await()} ${
            lock2.isLockedAsync.toCompletableFuture().await()
        }"
    ) // sometimes "IsLocked true false"
    delay(40000)
    println(
        "IsLocked ${lock1.isLockedAsync.toCompletableFuture().await()} ${
            lock2.isLockedAsync.toCompletableFuture().await()
        }"
    ) // still "IsLocked true false", watchdog isn't letting it expire
}
```
