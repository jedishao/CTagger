Event bus worker performance degradation in v4 compared to v3
While profiling my application I discovered a drastic degradation in performance in Vertx 4.x compared to Vertx 3.x in one particular scenario - sending messages over the event bus between worker verticles (or from an event loop verticle to a worker verticle).

I'm attaching a reproducer. I tested with Vertx 4.2.6 and 4.2.7 vs Vertx 3.9.9 on AdoptOpenJDK 8 and 11 on Windows 10. 

In the reproducer I have two worker verticles. One of them sends a message to another using event bus 'send'  method. The other verticle receives that messages and sends a response message to the first verticle, again using event bus 'send'. The first verticle receives the response and sends another message to the second one and so on and so on… Once a certain number of messages is sent, I print the stats and shutdown.

Here are some numbers. Same code, same JVM. The only difference is Vertx version.

Vertx 3.9.9: Message count: 1000000. Total time: 5479ms. Time per message exchange: 5479 nanos. TPS: 182501.31

Vertx 4.2.6: Message count: 1000000. Total time: 42263ms. Time per message exchange: 42263 nanos. TPS: 23661.273

It turned out that in version 4 a message is always posted to an event loop thread first and only from there it is delivered to the worker thread.
In version 3 the messages is added directly to the worker thread queue.

So, there is one extra hop between threads. In addition to that, that hop is always into an event loop thread, causing the posting thread to be blocked on wakeup call. All that adds up, as you can see in the numbers.

If you take a look at HandlerRegistration class, it’s “receive” method always posts to one of the event loop threads! It was not the case in Version 3. I'm attaching an image with some profiling results which clearly shows the stack trace.

The change appears to have been made in this commit: https://github.com/eclipse-vertx/vert.x/commit/e29acb4e06ac79d04e4f54ddcc5936deb74c5326

This looks like a bug to me. What an event loop thread has to do with a message which should be delivered to a worker thread? In my test case I do not have event loop verticles at all, yet I see two event loop threads which are very  busy.
