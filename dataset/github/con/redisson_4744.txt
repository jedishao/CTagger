When RedisReadWriteLock is used, two threads preempt a lock. For example, thread A has obtained the write lock, and another thread B is notified that it cannot obtain the read lock when it obtains the read lock. Then thread B subscribes. After thread B successfully subscribes but has not yet obtained the semaphore, thread A has unlocked and published a message. At this time, thread B has not yet tried to acquire, But at this time, the message on the server has been published, which will cause thread B to wait until the timeout.  we try to send an extra semaphore when publish a message, the problem disappear. Is this a bug?
