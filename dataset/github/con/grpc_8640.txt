ManagedChannel never terminates with shutdown/shutdownNow
<!-- Please answer these questions before submitting a bug report. -->

### What version of gRPC-Java are you using?
1.31.1
### What is your environment?
<!-- operating system (Linux, Windows,...) and version, jdk version, etc. -->
As a Kubernetes pod running /linux
openjdk version "1.8.0_302"
OpenJDK Runtime Environment (build 1.8.0_302-b08)
OpenJDK 64-Bit Server VM (build 25.302-b08, mixed mode)

### What did you expect to see?
Waits for the channel to become terminated, giving up if the timeout is reached.
### What did you see instead?
ManagedChannel.isTerminated() always return true after 100 or more tries shutdown()/shutdownNow()

### Steps to reproduce the bug

The issue gets reproduced intermediate and when observed the thread hangs. The channel stop is called using the following snippets.

<!-- Make sure you include information that can help us debug (full error message, exception listing, stack trace, logs). -->

        try
        {       
            channel.shutdown();     
            while (!channel.isTerminated())
            {
          
                try
                {
                    channel.awaitTermination(5, TimeUnit.SECONDS); 
                }
                catch (InterruptedException e)
                {
                    stopChannelLogger.warn(name + " GRPC channel client "+ clientId + " wait interrupted", e);
                }
                channel.shutdownNow();
            }
        }
        catch (Throwable e)
        {
            stopChannelLogger.warn(name + " GRPC channel client "+ clientId + " termination failed, will retry", e);
        }
