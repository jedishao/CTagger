Multi-query optimization
The calcite ticket [6188](https://issues.apache.org/jira/browse/CALCITE-6188) sums it up.

Devise extensions to SQL so that queries with multiple input tables, multiple intermediate tables, and multiple output data sets (result sets and DML operations) can be defined in one SQL statement, optimized together, and executed atomically.

We in Presto have a robust scheduling layer which supports plan sections and this could be way easier for us
