Add rewrite_table_path procedure to the Iceberg connector
Spark supports the [rewrite_table_path](https://iceberg.apache.org/docs/nightly/spark-procedures/?h=rewrite_ta#rewrite_table_path) procedure which can be used during table migrations and disaster recoveries.

Basically, because the paths to metadata files, data files etc. are hardcoded in the Iceberg manifests, just replicating the files to some other location renders them useless. 

Having a rewrite_table_path procedure would allow generating new meta files, with the updated storage location and that can then be used for things like restoring the tables in another storage location, copying the tables to some other environment etc.
