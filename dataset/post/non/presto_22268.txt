Geospatial function: ST_POLYGON() should make a polygon from an array of points
Currently the ST_POLYGON function in geospatial only acts exactly the same as ST_GEOMETRYFROMTEXT which might be a bug. These would duplicate functions.

ST_LINESTRING accepts an array of WKT points and allows making that into a linestring geometry, but feeding an array of points where the first point is the same as the last (so it is a closed polygon) to ST_POLGYON throws an error, which seems very unexpected and not consistent.

There is not otherwise a good way to take an array of WKT points and make them a polygon unless just doing a string concat with `POLYGON ((` and doing + for the coordinates.
