Optimize simple Iceberg queries using manifest file information
Iceberg tables are highly likely to contain column level statistics for each manifest file.

[Iceberg statistics include the number of distinct values, the number of nulls, the min and max values for each column, and the number of NaN values.](https://iceberg.apache.org/spec/#manifests). With knowledge of the presence of these statistics, we can simplify certain simple queries.  Some ideas for optimization:

* Simple min and max queries can use the statistics found in the manifest files, avoiding execution on the workers or simplifying the min/max functions to constant projections.
* Simple count(*) queries can similarly use manifest file statistics (using the records count).  If the function filters for non-null values, or contains just a predicate which filters nulls, then we could use the values count and subtract if nulls present.
* If there is a simple min_by or max_by query, and the ordering lines up with the sort_order specified in the manifest file, then we could leverage this information and filter only on files that can fulfill the aggregate functions.
* Simple TopN queries (ORDER BY + LIMIT) can leverage the sort_order found in the manifest file.  For example, if we want TopN of value orders, and orders is the sort field in the manifest file, we can schedule splits according to the max values found in the manifests.

Curious to see if there are other ideas on further opportunities for optimization.  I also admit that these help for only simple queries, and once complex predicates are introduced their usefulness decreases.
