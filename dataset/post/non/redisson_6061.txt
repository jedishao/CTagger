Redisson does not recover from DNS failures on master resolution for single-shard clusters
### Affected Versions

3.32.0 onwards. Validated with 3.31.0 and it was not present; 3.32.0, 3.33.0 and current `master` as of now are affected.

### Redis Cluster Details

* AWS ElastiCache
* Redis 6.2.6
* Instance t3.micro
* Cluster Configuration
    * 1 Shard (aka 1 Master)
    * 2 Slaves

### Issue Isolation

* Tried with different instances size; behaviour did not change.
* Tried with different amount of slaves; behaviour did not change.
* Tried with different amount of shards; behaviour DID change.

The issue is only reproducible on single-shard clusters.

### Issue Description

If Redisson detects a DNS resolution failure on the master node for a cluster, and there is only a single master (single shard), it never connects back again despite the DNS issue being fixed.

To reproduce, the following code was introduced into `ServiceManager.resolveAll` promise:

```
            String host = uri.getHost();
            if (host.contains("-001.")) {  // Target only masters
                if (!attemptCounter.containsKey(host)) {
                    attemptCounter.put(host, 0);
                }

                Integer attempt = attemptCounter.get(host);
                log.info("ATTEMPT {} for {}", attempt, host);
                attemptCounter.put(host, attempt + 1);

                if (attempt > 1 && attempt < 4) {
                    log.error("FORCING DNS FAILURE for {}", uri, f.cause());
                    result.completeExceptionally(new RuntimeException("Dummy"));
                    return;
                }
            }
```

The following was observed:

* On DNS success, everything works fine.
* When DNS failure occurs, it fails all connections.
* When DNS issue is mitigated, it resolves correctly the IP, but it does not connect back and from a Redisson client perspective, you cannot fetch any keys anymore.

I did try to replicate failure for ALL masters in multi-shard, but it connected back again correctly.

The initialization of Redisson is as follows:

```
        Config config = new Config();

        // Only one node of cluster configuration endpoint need to be specified - all other nodes are auto detected
        // SLAVE - Read from slave nodes, uses MASTER if no SLAVES are available.
        // MASTER - Read from master node,
        // MASTER_SLAVE - Read from master and slave nodes
        config.useClusterServers()
                .setReadMode(ReadMode.MASTER_SLAVE)
                .addNodeAddress(REDIS_DATABASE_URL)
                .setTimeout(REDIS_TIMEOUT)
                .setRetryAttempts(REDIS_RETRY_ATTEMPT)
                .setRetryInterval(REDIS_RETRY_INTERVAL)
                .setConnectTimeout(REDIS_CONNECTION_TIMEOUT);

        return Redisson.create(config);
```
