[native] Fix v1/operation end point
v1/operation end point is described in #21745 

Here, we document a few known issues with that endpoint that would be nice to fix.

Invalid values of parameters produce cryptic errors. For example, invalid value of limit for task/listAll return "500: stoi":

```
--cmd task/listAll?limit=abc

http error 500: stoi
```

systemConfig/getProperty doesn't reject non-existent properties:

```
--cmd systemConfig/getProperty?name=foo

 <default>
```

systemConfig/getProperty doesn't reject invalid values for properties:

```
--cmd "systemConfig/setProperty?name=task.max-drivers-per-task&value=abc"

Have set system property value 'task.max-drivers-per-task' to 'abc'. Old value was '123'.
```

Canonical REST uses GET for read-only operators and PUT/POST/DELETE for modifications. It would be more natural to define GET v1/operation/systemConfig?name=xxx to fetch current value and PUT v1/operation/systemConfig?name=xxx&value=yyy to update the value.
