Metadata not cached when using Iceberg REST catalog with S3Tables - ConnectorMetadata.getTableHandle takes ~200ms on every query
We are using Trino with the Iceberg REST catalog and AWS S3 as the backing storage. The Trino cluster consists of 1 coordinator and 3 workers (EC2 instances)

We have configured the catalog cache as follows:
```
fs.cache.enabled=true
fs.cache.directories=/mnt/ramdisk/trino-cache
fs.cache.max-sizes=2GB
fs.cache.ttl=1h
iceberg.metadata-cache.enabled=true
```
Despite this configuration, we observe that metadata is not being cached. Each query consistently spends more than 200ms on the `ConnectorMetadata.getTableHandle` operation.

<img width="1444" height="583" alt="Image" src="https://github.com/user-attachments/assets/3c590cd8-b9fa-4e9c-a7c2-f264bd4515e5" />

This happens even when running the same query repeatedly, either in parallel or sequentially. The metadata load appears to happen on every execution, indicating no effective caching.

We observe the same behavior when querying using `trino-cli` and with the Python client via `trino.dbapi`

Expectation:
The expectation is that metadata (such as table handles) would be cached and reused for repeated queries.

Question:
Is this the expected behavior with the Iceberg REST catalog, or is there something misconfigured or unsupported in this setup?
