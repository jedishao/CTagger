Reject X-Forwarded-* headers behaviour breaks requests
The fix described in #6552 (airlift/airlift#1183) now results in requests being rejected with a 406 error code when `X-Forwarded-*` headers are present but unwanted.

Broadly, I have the issues that @electrum describes as a potential issue in the comments. Some requests have been proxied and so have these headers.

Enabling `http-server.process-forwarded` is not desirable, because I do not want to trust the IP provided.
