Solve current limitations executing subqueries in WHERE clause using correlated conditions and the IN/NOT IN operator
Although Presto is able to execute qureies containing subqueries in the WHERE clause it has some limitations.
In particular, it seems to be limitations using correlated conditions + IN/NOT IN operator. Examples:


```
-- condition using escalar operator = and correlated condition with > : It does not fail although with low performance

SELECT * FROM tpch.sf1.orders o
WHERE 2 = (SELECT max(discount) FROM tpch.sf1.lineitem l WHERE l.orderkey > o.orderkey);


-- condition using escalar operator = and correlated condition with = : Works

SELECT * FROM tpch.sf1.orders o
WHERE 2 = (SELECT max(discount) FROM tpch.sf1.lineitem l WHERE l.orderkey = o.orderkey);


-- condition using EXISTS and correlated condition with = . Works

SELECT * FROM tpch.sf1.orders o
WHERE EXISTS (SELECT max(discount) FROM tpch.sf1.lineitem l WHERE l.orderkey = o.orderkey);

-- condition using IN and correlated condition with = . Fails

SELECT * FROM tpch.sf1.orders o
WHERE 2 IN (SELECT max(discount) FROM tpch.sf1.lineitem l WHERE l.orderkey = o.orderkey);

-- condition using IN and correlated condition with = without using alias for the joinned tables. Fails

SELECT * FROM tpch.sf1.orders 
WHERE 2 IN (SELECT max(discount) FROM tpch.sf1.lineitem  WHERE lineitem.orderkey = orders.orderkey);

-- condition using NOT IN and correlated condition with = . Fails

SELECT * FROM tpch.sf1.orders 
WHERE 2 not IN (SELECT max(discount) FROM tpch.sf1.lineitem  WHERE lineitem.orderkey = orders.orderkey);
```

## Expected Behavior or Use Case

The queries that fail should work

## Presto Component, Service, or Connector

The examples are using the tpch connector but It seems to be independent of the connector, it is possible to experience the same with the hive connector.


## Context

These failing queries look like pretty basic cases.
Tools that rely on Presto to execute certain queries do not have a clear way to identify these not supported scenarios to decide to send the query to Presto or not.
