Make the objectstore-secondary connection pool size configurable
The secondary connection factory is used for schema generation, and for value generation operations. Under normal circumstances 2 connections should be sufficient, however, we have found in HIVE-28839 that connection starvation may still happen. (in that case due to a datanucleus bug) 
We should make the "objectstore-secondary" pool size configurable. This is needed at least until a final fix is not available for HIVE-28839, but probably it is good to have on the long run if we find other edge cases too.
