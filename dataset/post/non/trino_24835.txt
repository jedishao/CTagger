This is much needed in debugging logs as each log refers to unique query id which is generated by trino and not the client. Typically, debugging is performed from the client side toward Trino, rather than the other way around.

In most cases, the client sends a trace_id (or correlation_id) using `X-Trino-Trace-Token`, but no corresponding trace_id exist in Trino logs. The only way to establish a link is through the following mapping:

**trace_id** → **query pattern from Trino Web UI** → **query_id** -> **trino logs**

However, due to the query.max-history setting being limited to 1,000, this information is often flushed from the Trino Web UI and system tables. When that happens, the only way to correlate Trino logs with client requests is by using timestamps—an approach that results in a poor debugging experience.
