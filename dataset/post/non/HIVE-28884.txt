Decouple source.q test from SRC dataset
Running source.q test independently fails due to missing SRC table.
{noformat}
mvn test -Dtest=TestMiniLlapLocalCliDriver -Dqfile=source.q
{noformat}
The test depends on the presence of the SRC table/dataset but the latter is not declared  explicitly with the {{qt:dataset}} command.

The failure was also observed in some CI runs where the test happened to run before a test loads the SRC dataset.

The purpose of the test is to verify that SOURCE CLI command (introduced in HIVE-1415) launches a SQL script but the content of the actual script is not really important.

I propose simplify the queries in the SQL script (source.txt) to avoid the aforementioned failures and avoid wasting resources on non relevant tests.
