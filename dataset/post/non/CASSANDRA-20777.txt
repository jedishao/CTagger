Improve Output of nodetool sstablerepairedset When Run Globally or Keyspace-Wide
When running {{nodetool sstablerepairedset}} globally or on a full keyspace, the output lacks keyspace and table context:
$ bin/nodetool sstablerepairedset --is-repaired
Previewing repaired state mutation of SSTables for all keyspaces to repaired
The following SSTables would be mutated:
oa-1-big
oa-2-big
This makes it unclear which SSTables belong to which keyspace/table — especially in multi-keyspace environments or when multiple {{data_file_directories}} are used.

{*}Suggested Fixes{*}:
 * Include keyspace and table names in the output.

 * Optionally include full SSTable paths if available.

 * If necessary, update {{mutateSSTableRepairedState}} to carry more metadata (added via the CEP work).
