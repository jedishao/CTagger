Vulnerable airlift_aircompressor as part of trino 446 which is using stable jdk (21v)
Aircompressor is a Java library that ports the Snappy, LZO, LZ4, and Zstandard compression algorithms. However, all decompressor implementations in Aircompressor (LZ4, LZO, Snappy, Zstandard) can cause the JVM to crash with certain inputs and potentially leak other memory contents of the Java process, which could include sensitive information. This issue arises because the decompressors may attempt to access memory outside the bounds of the provided byte arrays or byte buffers. Aircompressor leverages the JDK class sun.misc.Unsafe to enhance memory access speed, but this bypasses additional bounds checks, leading to security risks similar to out-of-bounds access in C or C++, which can result in non-deterministic behavior or JVM crashes. Users should upgrade to Aircompressor 0.27 or later, where these issues have been resolved. If decompressing data from untrusted sources, this vulnerability can be exploited to execute a denial-of-service attack by crashing the JVM or to leak sensitive information from the Java process (https://nvd.nist.gov/vuln/detail/CVE-2024-36114).

We are planning to use the stable JDK 21, which is only supported up to Trino version 446. We request that this issue be addressed in Trino 446 or another trino version with this vulnerability fix in JDK 21.
