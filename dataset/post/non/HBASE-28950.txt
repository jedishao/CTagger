After modifying the 'zookeeper.znode.parent' parameter and restarting HBase, HBase is unable to complete its initialization.
In my tests, after modifying the 'zookeeper.znode.parent' parameter and restarting HBase, HBase is unable to complete its initialization with versions 2.3.* and 2.4.* , but this issue does not occur with version 2.2.* .

If the Zookeeper cluster crashes and the data stored in zk cannot be recovered, and only a new ZK cluster can be set up, the HBase cluster will never be able to return to a normal state. This problem is particularly severe under certain failure scenarios.

 

The following describes the situation after I modified the znode and restarted HBase. The data in the hbase:meta table was lost, the number of regions displayed on the Master UI remained at 1, and the meta table could not come online. Moreover, there were no obvious error messages found in the logs of the Master or Region Servers.

 

Maybe it's related to the issue fixed by HBASE-26193?
