Access Control on groups retrieved from OAuth authentication does not work
## Current setup
- Trino 475
- OAuth authentication with Azure ID
  - Configuration to retrieve the principal from the token: `http-server.authentication.oauth2.principal-field=oid`
  - Configuration to retrieve the groups from the token: `deprecated.http-server.authentication.oauth2.groups-field=roles`


The issued authorization token contains both of the fields:
```json
  "oid": "40193f55-f6b7-4572-8fc0-b8078db97b1a",
  "roles": [
    "Trino.Admin",
    "Trino.ReadOnly"
  ],
```

Debug logs from the Coordinator show both of the groups retrieved from the roles for my principal, as expected:
```
2025-08-01T18:02:20.229Z    DEBUG    Query-20250801_180219_00014_ynqv7-652    io.trino.security.AccessControl    Invocation of getRowFilters(context=SecurityContext{identity=Identity{user='40193f55-f6b7-4572-8fc0-b8078db97b1a', groups=[Trino.Admin, Trino.ReadOnly], principal=40193f55-f6b7-4572-8fc0-b8078db97b1a}, queryId=20250801_180219_00014_ynqv7}, tableName=c_common.information_schema.tables) succeeded in 34.59us
```

Access control configuration has rules based on groups:
```yaml
  accessControl:
    type: configmap
    refreshPeriod: 60s
    configFile: "rules.json"
    rules:
      rules.json: |-
        {
          "catalogs": [
            {
              "group": "Trino.Admin",
              "allow": "all"
            },
            {
              "group": "Trino.ReadOnly",
              "allow": "read-only"
            },
            {
              "user": "superset",
              "allow": "read-only"
            }
          ],
          "schemas": []
        }
```

## Issue

In Trino 474 this setup was working fine, but after upgrading to 475 or 476 we no longer see results for `SHOW SCHEMAS` and `SHOW TABLES` for users logged in with OAuth:

```
trino> show schemas in c_common;
```
