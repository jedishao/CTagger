CTE Materialization creating wrong plans for similar named ctes in completely different scope
Materialization of CTEs involves identifying their usage through CTE names and relative paths. However, there are two identified bugs in this process, which have been noticed in 0.2% of production queries. 

In Presto SQL, the allowance for nested and similarly named CTEs in numerous instances contributes to these issues.


Observed 2 edge cases from production

edge case 1 : 
 Local scope is not always prioritized over global scope.

```
WITH test AS (SELECT 1),
_query AS (
   with test AS (
         SELECT * FROM test. <<---- marked**
 )
 SELECT * FROM test
)
SELECT * FROM _query JOIN _query on true
```
Here the marked use of test should be from outside of the current scope. Using cte_materialization_strategy='ALL' gives a graph cycles error

edge case 2:
 

```
  SELECT   *, (WITH T as (SELECT 1) SELECT * FROM T)
                       FROM (
                        WITH T AS ( 
                          SELECT ColumnA, ColumnB FROM (
                               VALUES 
                                 (1, 'A'),
                               (2, 'B'),
                                 (3, 'C'),
                                 (4, 'D')
                             ) AS TempTable(ColumnA, ColumnB)
                         )
                         SELECT * FROM T
```

Here project and from clause both have a completely new scope creating the same CTE t, hence the cte name key should have this baseline value in it so that wrong ctes are not used at the wrong places.
