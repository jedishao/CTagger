Integrate SAI's index state and query performance metrics w/ nodetool tablestats
The output structure of {{nodetool tablestats}} might be amenable to adding a number of SAI state/performance metrics, which are predominantly table-scoped. (There are some that are scoped at the column level, of course, but the table-level items could be useful if we don't want to directly call JMX and want a general idea of how we're doing with things like post-filtering read latency.)

The decisions we have to make are along the lines of "What percentile to use for post-filtering read latency?", but I imagine we can follow whatever existing pattern exists.
