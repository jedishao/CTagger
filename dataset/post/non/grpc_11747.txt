XdsTestServer: server_id field not up to spec
Unless provided via `--server_id` shell argument, XdsTestServer sets `SimpleResponse.server_id` to the default  `"java_server"`:

https://github.com/grpc/grpc-java/blob/921f88ae30e5a4b1d890f3ea7ff709f475a86298/interop-testing/src/main/java/io/grpc/testing/integration/XdsTestServer.java#L87

https://github.com/grpc/grpc-java/blob/921f88ae30e5a4b1d890f3ea7ff709f475a86298/interop-testing/src/main/java/io/grpc/testing/integration/XdsTestServer.java#L330-L332

```console
❯ docker run --rm us-docker.pkg.dev/grpc-testing/psm-interop/java-server:v1.69.x --help
Usage: [ARGS...]
...
  --server_id=STRING  server ID for response.
                      Default: java_server
...
```

However, according to the spec, this field is supposed to be unique per server instance:
https://github.com/grpc/grpc-java/blob/921f88ae30e5a4b1d890f3ea7ff709f475a86298/interop-testing/src/main/proto/grpc/testing/messages.proto#L118-L120

This doesn't seem to break anything now (except the spec :trollface:).
However, since Java's xds test server implementation is considered canonical, we should fix this.
