_*fs.listFiles(path, true)*_
    - This recursively lists {*}all files{*}, even those that may be obsolete or deleted during iteration. So if Hive's cleaner deletes {{base_000002}} _after_ it's discovered by {{listFiles()}} but _before_ {{hasNext()}} tries to access it (for metadata resolution), we get a {{{}FileNotFoundException{}}}.

There is a fix for this issue in Hadoop upstream HADOOP-18662
This was discovered when run hadoop version without this fix.

But why list all the files recursively irrespective of the current write id which is unnecessary which we will be filtering out later.
Need to optimize from hive side to see if we can filter and list only current write id files from hdfs.
