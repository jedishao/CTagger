Inconsistent use of Language and FunctionImplementationType
There is a mix-up in the current PrestoDB code between `Language` and `FunctionImplementationType`. FunctionImplementationType incorrectly includes languages like JAVA and CPP, which should be classified as languages rather than implementation types.

```
public enum FunctionImplementationType
{
    JAVA(false, true),
    SQL(false, true),
    THRIFT(true, false),
    GRPC(true, false),
    CPP(false, false),
```
    
```
public class RoutineCharacteristics
{
    @ThriftStruct
    public static class Language
    {
        public static final Language SQL = new Language("SQL");
        public static final Language CPP = new Language("CPP");
```

## Presto Component
presto-spi

## Suggested Fix:
Refactor FunctionImplementationType to better align with actual implementation types (such as SQL, GRPC, etc.).
Ensure RoutineCharacteristics.Language only handles programming languages.
This will help avoid further confusion and make the code more maintainable.
