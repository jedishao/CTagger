Prometheus authentication fails, unexpected 0x0a at the end of the token
In the PrometheusClient, the file containing the Prometheus authentication token is read by a readString() method. The file does not have an line ending character at the end (neither 0x0d or 0x0a) but the string created by the method does. This causes an error when the client attempts to Authenticate with Prometheus. 

The solution proposed is to strip `\n` nd `\r` from the results of the readString(). 

A PR has been submitted with this patch: https://github.com/trinodb/trino/pull/22817
