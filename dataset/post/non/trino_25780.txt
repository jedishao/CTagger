Trino forgets vended-credentials in S3FileSystem::deleteObjects
Hi, 


## Problem

When executing `expire_snapshots` on an iceberg table with Trino 475, we're encountering missing credentials errors that didn't occur on Trino 467. The root cause seems to be in `S3FileSystem::delete_objects` where the second call to `overrideConfiguration()` on the builder overwrites the `credentialsProvider` set by the first call. 

## Reproduction

`expire_snapshots` on an iceberg table on an s3-compatible storage with a rest catalog & "iceberg.rest-catalog.vended-credentials-enabled" = 'true' using Trino 475

## Details

In `src/main/java/io/trino/filesystem/s3/S3FileSystem.java`, two consecutive calls to `Builder::overrideConfiguration` occur:

1. First call: `overrideConfiguration(context::applyCredentialProviderOverride)`, sets credential, essential for vended-credentials to work in iceberg 
2. Second call: `overrideConfiguration(disableStrongIntegrityChecksums())`, a workaround for missing strong integrity checks in some storage providers:


The second `overrideConfiguration` nulls the previously set `credentialsProvider` in the `awsRequestOverrideConfig`. This then causes the delete request to fail with:
