camel-ftp - Consumer and antInclude regression
Based on modifications in SftpConsumer and FtpConsumer classes, with new getRelativeFilePath method, file names from root FTP folder are now returned as relative, so e.g. "/fileName.csv", instead of previous "fileName.csv". This change causes a regression in antInclude filters, not working anymore (maybe this is a desired breaking change, but undocumented).

Previous working antInclude parameter: "*" - get all files in root FTP directory

From 4.10 and on, same parameter values matches no files

AntInclude parameter now follows previous behavior using: "/*" - all file names become relative

SftpConsumer#doPollDirectory -> GenericFileConsumer#isValidFile -> GenericFileConsumer#isMatched -> AntFilter#accept -> AntPathMatcherFileFilter#acceptPathName -> 
matcher.match(include, path, caseSensitive) skips now all files, starting with relative path "/"
