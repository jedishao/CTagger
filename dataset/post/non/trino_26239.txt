Add an official MCP (Model Context Protocol) Server


### Is your feature request related to a problem?

As AI agents and LLMs become a primary interface for data analytics, they require rich, structured context about database schemas to generate accurate SQL. Currently, an agent interacting with Trino must perform many slow, iterative metadata queries (`SHOW TABLES`, `DESCRIBE`, etc.) to build this context, which is inefficient and often incomplete.

### Describe the solution you'd like

I propose that Trino implement a built-in **MCP (Model Context Protocol) server**. This would expose Trino's vast federated metadata through a single, standardized endpoint.

An AI agent could then make a single `getContext` request to Trino's MCP server and receive a complete, structured description of the available catalogs, schemas, tables, columns, and their relationships.

### Why is this a good idea?

1.  **Unified Context for the Enterprise:** Trino's unique strength is its ability to query across dozens of data sources. An MCP server would make Trino the single, unified context provider for an organization's entire data landscape, a killer feature for enterprise AI.
2.  **Dramatically Improved Efficiency:** It replaces numerous round-trips for metadata with a single, optimized call, making AI-driven data interaction significantly faster.
3.  **Keeping Pace with the Industry:** The MCP standard is gaining rapid adoption. Major databases like **Oracle** and modern query engines like **StarRocks** have already implemented official MCP servers. For Trino to remain a leading, modern data engine, supporting this protocol is essential.
4.  **Enables Powerful AI Use Cases:** This feature would unlock the seamless development of natural language-to-SQL agents that can intelligently query all data sources connected to Trino.

Adding an MCP server would be a strategic enhancement, solidifying Trino's position as the central query and context layer for the AI-powered data stack. Thank you for your consideration.
