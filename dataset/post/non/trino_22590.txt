millisecond precision issue of the TIMESTAMP_MILLIS type in the ES connector
I'm using the trino418 and ES connector, there is an SQL query: select id,create_time from test_index where create_time<=cast('2023-09-28 16:05:48.000' as timestamp) limit 10, and I found a record with create_time='2023-09-28 16:05:48.742' was returned. 
I used the ES API to query:
{
  "query": {
    "bool": {
      "filter": [
        {
          "term": {
            "create_time": {
              "value": "2023-09-28T16:05:48",
              "boost": 1.0
            }
          }
        }
      ],
      "adjust_pure_negative": true,
      "boost": 1.0
    }
  }
}
This query returns the record, but using:
{
  "query": {
    "bool": {
      "filter": [
        {
          "term": {
            "create_time": {
              "value": "2023-09-28T16:05:48.000",
              "boost": 1.0
            }
          }
        }
      ],
      "adjust_pure_negative": true,
      "boost": 1.0
    }
  }
}
does not return the record.

Therefore, I found the following code and noticed that the format discards the millisecond part '.000'. Should we use a format like "yyyy-MM-dd'T'HH:mm.SSS" here?
