Inconsistent MaxInactiveInterval Setting in Sessions in multi-node Tomcat environment
### Redis version

7.2.4

### Redisson version

3.37.0

### Redisson configuration

masterSlaveServersConfig:
        masterAddress: "rediss://${REDIS_HOST}:${REDIS_PORT}"
        username: ${REDIS_USERNAME}
        password: ${REDIS_PASSWORD}
        readMode: "MASTER"
        connectTimeout: 30000
        timeout: 10000
        masterConnectionPoolSize: 20
        masterConnectionMinimumIdleSize: 1
      codec: !<org.redisson.codec.SerializationCodec> {}

### What is the Expected behavior?

On successful login after session creation, when MaxInactiveInterval value is updated it should apply consistently to all the user sessions across all the nodes.

### What is the Actual behavior?

I am experiencing an issue where the MaxInactiveInterval for HTTP sessions is not consistently applied to tomcat nodes when users log in. The default session timeout is set to 60 minutes, but I have a method to set a dynamic timeout based on tenant-specific configurations. 

After users log in, some user sessions get MaxInactiveInterval value based on the tenant while others get default value of 60. 

### Additional information

This example code demonstrates the usage:

```java
void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
    Instant now = Instant.now();
    HttpSession session = req.getSession();
    
    session.setMaxInactiveInterval(getDynamicValuePerTenant()); // Value set dynamically

    PrintWriter writer = resp.getWriter();
    writer.println(String.format("pong: %s, sessionId: %s, instance: %s, inactiveTimeOut: %s", 
        now, session.getId(), Node.id(), session.getMaxInactiveInterval()));
    writer.flush();
}
```

After the session is created, some user sessions reflect the correct `MaxInactiveInterval` based on their tenant settings, while others default to 60 minutes. This behavior appears random and may be due to the asynchronous handling of session updates.

To test this hypothesis, I introduced a 300ms delay as follows:

```java
void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
    Instant now = Instant.now();
    HttpSession session = req.getSession();
    try {
        Thread.sleep(300);
    } catch (InterruptedException e) {
        throw new RuntimeException(e);
    }
    session.setMaxInactiveInterval(getDynamicValuePerTenant());

    PrintWriter writer = resp.getWriter();
    writer.println(String.format("pong: %s, sessionId: %s, instance: %s, inactiveTimeOut: %s", 
        now, session.getId(), Node.id(), session.getMaxInactiveInterval()));
    writer.flush();
}
```

With the delay, the `MaxInactiveInterval` was consistently set as expected.

Is there a flag that can be used or introduced to ensure that `setMaxInactiveInterval` is performed synchronously?
