[ MongoDB Connector ] Presto MongoDB connector attempts SCRAM-SHA-1 authentication despite server supporting only SCRAM-SHA-256


## Describe the problem you faced

I am using Presto version 0.292 with the MongoDB connector to connect to a MongoDB cluster (I'm in kubernetes). The MongoDB users are configured to authenticate using SCRAM-SHA-256 only; SCRAM-SHA-1 is disabled on the server.

However, when Presto tries to connect, the logs show that it attempts to authenticate using SCRAM-SHA-1, which is rejected by the MongoDB server with the following error:

`com.mongodb.MongoCommandException: Command failed with error 334: 'Received authentication for mechanism SCRAM-SHA-1 which is not enabled'`

This causes the authentication to fail and prevents Presto from connecting to MongoDB.

I have verified that:

- The MongoDB user’s authentication mechanism is SCRAM-SHA-256 (no SCRAM-SHA-1).
- The MongoDB server has SCRAM-SHA-1 disabled.
- Presto’s configuration does not explicitly specify an authentication mechanism.
- Logs from Presto indicate it excludes SHA-1 cipher suites in HTTP client config, yet still attempts SCRAM-SHA-1 for MongoDB authentication.

This leads me to believe that the MongoDB connector or its underlying driver in Presto is defaulting to SCRAM-SHA-1 without a way to override or negotiate the mechanism.


## Environment Description

* Presto version used: 0.292
* Data source and connectors or catalogs used: MongoDB (version 8.0.5 mongodbcommunity)
* Deployment (Cloud or On-prem): On-prem


## Impact

- Unable to connect to MongoDB clusters configured with SCRAM-SHA-256 only.
- No configuration option in Presto to specify or enforce SCRAM-SHA-256 as the authentication mechanism.
- Restarting Presto or modifying certificates does not help since the authentication attempt always uses SCRAM-SHA-1.

## Expected behavior

Presto should either detect and use SCRAM-SHA-256 automatically, or allow the user to specify the authentication mechanism in the MongoDB connector configuration.

Alternatively, the MongoDB driver used by Presto should negotiate the authentication mechanism supported by the server.
