## Writing Principle:

### Incremental indexing of serialized memory
In the process of writing incremental indexes in Druid, when the amount of data in memory reaches a certain threshold, it needs to be flushed to disk. Before flushing to the hard drive, the incremental index in memory needs to be serialized. If the size of serialization exceeds `fileSizeLimit = Integer.MAX_VALUE & ~PAGE_SIZE`, the write position will be reset, and it will be recorded in headerOutLong.

### Pre-writing temporary files
Druid calculates the appropriate bagSize using headerOutLong, the number of rows, and the total number of bytes, and then generates a byte array. This byte array is pre-written to temporary files, which are stored in the completedFiles list.

### Merge temporary files to generate a segment
Druid merges the list of files (completedFiles) into relatively larger smoosh files. The merging logic involves iterating through completedFiles and requires that `specBytes.size() + serdeficator.getSerializedSize()` not exceed `Integer.MAX`. Due to the initial division point of headerOutLong not taking into account specBytes.size() and the order of writing, there is a certain probability that `specBytes.size() + serdeficator.getSerializedSize()` may exceed `Integer.MAX_VALUE`, leading to a request buffer failure.

## Recommendation:
Reduce the value of `fileSizeLimit`, for example, change it to: `fileSizeLimit = (Integer.MAX_VALUE & ~PAGE_SIZE)*0.8`, or expose `fileSizeLimit` as a configurable property.
