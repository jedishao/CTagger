FYI, I got the similar error with this query via table function
```
trino> SELECT
    ->   *
    -> FROM
    ->   TABLE(
    ->     demo_postgres.system.query(
    ->       query => 'SELECT *
    ->       FROM public."ConversationMessage"
    ->       WHERE role::ConversationMessageRole = ''user'''
    ->     )
    ->   );
Query 20240729_063026_01511_et9cn failed: Failed to get table handle for prepared query. ERROR: type "conversationmessagerole" does not exist
  Position: 70
```
However, If I wrap the **ConversationMessageRole** type under double quotes, it works normally.
```
trino> SELECT
    ->   *
    -> FROM
    ->   TABLE(
    ->     demo_postgres.system.query(
    ->       query => 'SELECT *
    ->       FROM public."ConversationMessage"
    ->       WHERE role::"ConversationMessageRole" = ''user'''
    ->     )
    ->   );
```
The origin table name is **ConversationMessage**, the column **role** type is enum varchar, with the user-defined type name is **ConversationMessageRole**. This is my catalog config:
```
case-insensitive-name-matching=true
connection-password=<password>
connection-url=jdbc\:postgresql\://<host>\:<post>/db
connection-user=postgres
connector.name=postgresql
decimal-mapping=allow_overflow
decimal-rounding-mode=HALF_UP
```
My guess is that Trino doesn't preserve the column constraint name casing when type-casting columns that their types are user-defined (enum in this case) even if `case-insensitive-name-matching` is set to `true`
