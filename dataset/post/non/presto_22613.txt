presto-cli should not print stack trace for recognized user error 
Here's an error I just got. This is fine. The query is syntactically incorrect. I should have quoted $row_id. This is a user mistake and presto-cli correctly recognized and reported it. 

What presto shouldn't do in this case is print a stack trace. There's no internal failure here, or any debugging to be done inside presto. The stack trace is inappropriate useless cruft. It blurs the distinction between presto users and presto developers. Syntactically incorrect user input is not an exceptional condition. It is an expected and regular occurrence. Even if exceptions are used internally for managing this, it should not be exposed to end users.
