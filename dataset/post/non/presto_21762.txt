INACTIVE node state of worker is not respected by coordinator.
When worker returns INACTIVE as the node state - it is being ignored by the coordinator.
The coordinator still returns 'active' status in "select * from system.runtime.nodes;" query.
The queries continue to be scheduled at the worker.

"curl -k http://twshared36083.02.pnb2:7777/v1/info/state" from the worker returns INACTIVE.

Note that SHUTTING_DOWN state works: the node removed from the list of active nodes.

DiscoveryNodeManager has some code to deal with INACTIVE and it must have a bug.
