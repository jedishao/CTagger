Inconsistent behavior of LIKE operator
<!--- Provide a general summary of the issue in the Title above -->
<!--- Look through existing open and closed issues to see if someone has reported the issue before -->

I noticed that LIKE operator behaves differently for these two logically-equivalent queries.
1. `SELECT c0 LIKE c1 ESCAPE '' FROM (VALUES ('a_c', 'a_%'), ('_cd', 'a_%')) AS t(c0, c1);`. Presto returns two rows: true, false.
2. `SELECT c0 LIKE 'a_%' ESCAPE '' FROM (VALUES ('a_c', 'a_%'), ('_cd', 'a_%')) AS t(c0, c1);`. Presto throws an error "Escape string must be a single character".

I expect these two queries to both throw the exception (since if the escape string is empty, the ESCAPE part of the query can be simply removed).

We noticed this inconsistency while verifying Velox results against Presto in Velox fuzzer tests. Velox always throws the exception when escape string is empty.
