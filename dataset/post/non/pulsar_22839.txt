### Version

Apache Pulsar 3.0.4
Apache Pulsar Helm Chart 3.4.0
Kubernetes v1.27.13

### Minimal reproduce step

Newly installed on Kubernetes using the Helm Chart

Change retention policy:
`curl -vX POST -H 'Content-Type: application/json' http://{ip-address}/admin/v2/namespaces/public/default/retention -d '{"retentionSizeInMB": -1, "retentionTimeInMinutes": -1}'`

Set offload configuration on namespace:
`curl -vX POST  http://{ip-address}/admin/v2/namespaces/public/testing/offloadPolicies -h "Content-Type: application/json" -d '{"s3Driver":true,"managedLedgerOffloadDriver":"S3","offloadersDirectory":"offloaders","s3ManagedLedgerOffloadBucket":"apache-pulsar-offload","s3ManagedLedgerOffloadRegion":"{region}","s3ManagedLedgerOffloadServiceEndpoint":"https://{endpoint}"}'`

Create new topic:
`curl -vX PUT http://{ip-address}/admin/v2/persistent/public/default/test`

Create a new subscription

`curl -vX PUT http://{ip-address}/admin/v2/persistent/public/default/test/subscription/sub`

Write Messages to the topic.

Get ledgerId:

`curl -v http://{ip-address}/admin/v2/persistent/public/default/test/internalStats`

Trigger offload with the following command:

`curl -vX PUT http://{ip-address}/admin/v2/persistent/public/default/test/offload -H 'Content-Type: application/json' -d '{"ledgerId":{ledgerID},"entryId":1,"partitionIndex":-1,"batchIndex":-1,"batchSize":0}'`

Check offload status:
`curl -v http://{ip-address}/admin/v2/persistent/public/default/test/offload`

Answer:
`{"status":"SUCCESS","lastError":"","firstUnoffloadedMessage":{"ledgerId": ledgerID},"entryId":0,"partitionIndex":-1,"batchSize":0,"batchIndex":-1}}`

### What did you expect to see?

Files on the S3-Storage and logs on the brokers describing the course of the operation.

### What did you see instead?

While the answer indicates everything went fine, no files were uploaded to the S3-Storage.
