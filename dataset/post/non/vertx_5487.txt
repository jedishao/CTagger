Memory leak bug in Http1xClientConnectionClass


### Version

Which version(s) did you encounter this bug ? 4.2.6

### Context

In http1xClientConnection.handleHttpMessage() the code throws a "Received HTTP message with no request in progress" exception when a response is received without a request in progress. In this case, the content of a DefaultHttpContent is a byteBuf and hold data.  Per netty's reference counted objects documentation, the code should release the byteBuf buffer before throwing the exception, as nothing will access it anymore.
_The general rule of thumb is that the party that accesses a reference-counted object last is also responsible for the destruction of that reference-counted object. Specifically:

    If a [sending] component is supposed to pass a reference-counted object to another [receiving] component, the sending component usually does not need to destroy it but defers that decision to the receiving component.
    If a component consumes a reference-counted object and knows nothing else will access it anymore (i.e., does not pass along a reference to yet another component), the component should destroy it._
  

### Do you have a reproducer?
The code was ran in Http1xTest class in the vertx code.

    try {
      server.listen(testAddress, onSuccess(v -> {
        isConnected.set(true);

            Thread.sleep(100);

          }
      }
      //System.out.println("Server is connected");

      for (int i = 0 ; i < requestNum; i++) {
        vertx.createHttpClient(new HttpClientOptions().setMaxInitialLineLength(6000))
          .request(new RequestOptions(requestOptions).setURI("/?t=" + longParam))
          .compose(HttpClientRequest::send)
          .onComplete(onSuccess(resp -> {
            resp.bodyHandler(body -> {
              //System.out.println("Received response");
