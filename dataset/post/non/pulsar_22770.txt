Enhancement: Clearly define REST API on Open API
### Search before asking

- [X] I searched in the [issues](https://github.com/apache/pulsar/issues) and found nothing similar.


### Motivation

We provide this link for users to view the definition of REST API: https://pulsar.apache.org/admin-rest-api/?version=3.0.5

However, there are several issues currently:

1. For `POST, PUT, DELETE` requests, we do not have a clear definition of success codes. For example: https://pulsar.apache.org/admin-rest-api/?version=3.0.5#operation/Bookies_deleteBookieRackInfo The code typically returns 204 or 200.

2. For some GET requests, the response structure type is not declared. For example: https://pulsar.apache.org/admin-rest-api/?version=3.0.5#operation/Namespaces_getSubscriptionAuthMode In the code, it returns: [SubscriptionAuthMode](https://github.com/apache/pulsar/blob/17bb3227536f891d4f2ef234da596bdb5bb46bbb/pulsar-broker/src/main/java/org/apache/pulsar/broker/admin/v2/Namespaces.java#L1468)

3. There are also some GET requests where the returned structure type is incorrect. For example: https://pulsar.apache.org/admin-rest-api/?version=3.0.5#operation/BrokerStats_getBrokerResourceAvailability Because in the code, we use [interfaces](https://github.com/apache/pulsar/blob/3158fd3550f9e3a0b2c0316c92265318b209f4f5/pulsar-broker/src/main/java/org/apache/pulsar/broker/loadbalance/ResourceUnit.java#L24), and interfaces do not necessarily represent the actual data of entities.

4. There are also some API that return data in the format of `Map<String, List<Object>>`, which Swagger API does not support parsing. For example: https://github.com/apache/pulsar/blob/17bb3227536f891d4f2ef234da596bdb5bb46bbb/pulsar-broker/src/main/java/org/apache/pulsar/broker/admin/v2/Namespaces.java#L242


### Solution

1. We need to check each interface to ensure that it clearly defines the request parameters and response structure in Swagger.
2. For the types of interfaces that return data, it's best to convert them into entities and declare them. Alternatively, you can annotate their content for users to refer to in the source code, ensuring that incorrect content is not returned.

4. For the type of `Map<String, List<Object>>`, we need add some information to `note`.
