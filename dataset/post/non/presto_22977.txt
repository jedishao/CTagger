Wrong results for count (and probably correlated subqueries) over empty grouping sets
QueryCardinalityUtils is checking for global aggregations incorrectly.  It's only checking if an aggregation has an empty grouping set, but not if the empty grouping set is the only one. https://github.com/prestodb/presto/blob/master/presto-main/src/main/java/com/facebook/presto/sql/planner/optimizations/QueryCardinalityUtil.java#L108-L110

Since QueryCardinalityUtils is used for correctness purposes for plan rewrites, this can cause wrong results. For example:

```
// this query returns 3 rows
presto:di> SELECT count(*) from (values(1),(2)) t(x) GROUP BY GROUPING SETS ((x),());
 _col0 
-------
     2 
     1 
     1 
(3 rows)

// the count over this query returns a count of 1 because [PruneCountAggregationOverScalar](https://github.com/prestodb/presto/blob/master/presto-main/src/main/java/com/facebook/presto/sql/planner/iterative/rule/PruneCountAggregationOverScalar.java) gets applied 
presto:di> SELECT count(*) from (SELECT count(*) from (values(1),(2)) t(x) GROUP BY GROUPING SETS ((x),()));
 _col0                
-------
     1 
(1 row)
```

There are other optimizations using this that relate to correlated subqueries, and those presumably would also have similar correctness issues.
