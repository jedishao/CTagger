Presto silently converts NaN to zero when casting it to an INTEGER but throws when casting to BIGINT.
Since NaN cannot be represented as an integer value, it would make sense to instead return a user error similar to how it does when casting to BIGINT.

```
SELECT CAST(NAN() AS INTEGER) ;  ---- 0
SELECT CAST(NAN() AS BIGINT) ;  ---- Error:  Unable to cast NaN to bigint
```
