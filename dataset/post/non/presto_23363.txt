Allow for plan hash comparisons to be support after DetermineJoinDistributionType completes for HBO Retry Support
Currently it is Presto codebase and retry is set up so that, if a query fails and HBO can change the query plan it will continue executing (Check Query.java). However, we would ideally like to support checking the plan change after all the optimizers (in this case particularly DetermineJoinDistributionType). 

This issue is to have the plan hash comparison support this, still while ensuring the query only re-executes if the plan hash has changed.
