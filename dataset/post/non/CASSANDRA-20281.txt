Capability to run repair before replacing a node
It is vital to repair the token range of the node being replaced to avoid data loss as part of a node replacement.

There is no better mechanism to repair a node before replacing it. As part of this ticket, we can discuss various ideas for extending the AutoRepair framework.

There are four different ways to remove a node from the ring:
 # nodetool decommission
 # -Dcassandra.replace_address=<IP_of_dead_node>
 # nodetool assassinate
 # nodetool removenode
