[Bug] receiver_queue_size is not honoured with partitioned topic
### Search before asking

- [X] I searched in the [issues](https://github.com/apache/pulsar/issues) and found nothing similar.


### Version

Pulsar version 2.10.4
OS: Ubuntu(version=22.04)
Client(Python): pulsar-client(Version=3.3.0)

### Minimal reproduce step

1. Create a partitioned topic with one partition
    `bin/pulsar-admin topics create-partitioned-topic persistent://public/default/test-consumer -p 1`
2. Publish some messages
3. Create one consumer as following
    `consumer = client.subscribe(
topic='persistent://public/default/test-consumer',
subscription_name='test',
consumer_type=ConsumerType.Shared,
initial_position=InitialPosition.Earliest,
receiver_queue_size=1,
max_total_receiver_queue_size_across_partitions=1,
consumer_name=None,
negative_ack_redelivery_delay_ms=60000,
unacked_messages_timeout_ms=3600000)`
4. Receive and ack one message
`consumer.receive(timeout_millis=30000)`
`consumer.acknowledge(message=message_id)`
5. Check stats(Its showing 2 unack messages but its not received yet, also if we create another consumer and try to consume messages its not delivering)

### What did you expect to see?

It should not show 2 unack messages before even receiving messages since receiver size is 1.
