RedissonLock - infinity loop of acquiring/releasing, the number of available permits is greater than 1.
### Redis version

7.2.3

### Redisson version

3.32.0

### Redisson configuration

Single server with default settings.

### What is the Expected behavior?

The `RedissonLock` should work properly and the number of available permits in the lock should be always 0 or 1, it never should be greater.

### What is the Actual behavior?

Due to network issues(?), the locking mechanism starts working in the wrong way. The number of permits held by lock increases unexpectedly above 1. In this case, the publisher thread falls into an infinite loop of acquiring/releasing. 

### Additional information

## Issue
Some time ago we decided to switch from the `RedissonBlockingQueue` to the `RedissonPriorityBlockingQueue`. The application has worked stable for 2-3 days and unexpectedly stopped working. After a deeper investigation, we have noticed that the problem is related to the `RedissonLock` and its locking mechanism. The publisher thread falls into an infinite loop of acquiring/releasing. This happens because the number of available permits held increases unexpectedly above 1. The lock is never removed and publish is never executed.

## Steps to reproduce in local environment
Unfortunately, I was unable to simulate a real network issue locally, but I have reproduced the issue using the `CLIENT PAUSE` command on the Redis server. Here are the steps that I did to catch the infinite loop of acquiring/releasing:
1. Run the application in a debug mode
2. Set up break-point in like 108 of the `RedissonLock` class.
    `Long ttl = tryAcquire(-1, leaseTime, unit, threadId);`
3. Set up a break-point whenever in the code after putting the task in the priority queue.
4. Trigger putting a new task to the priority queue.
5. The debugging stops at line 108 of the `RedissonLock` class.
6. Execute the client pause command on the Redis server.
    `redis-cli CLIENT PAUSE 6000`
7. Resume the application.
8. The publisher thread stops working.
9. Repeat steps 4-7 a few times if need to catch the infinite loop of acquiring/releasing.
