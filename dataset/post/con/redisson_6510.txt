Why doesn't RFencedLock  remove "redisson_lock_token" after releasing the lock?
Redisson version: 3.45.1  

Recently, I have done a  statistics about the usage of Redis keys in our production environment, and found about 25 million "redisson_lock_token" prefix keys in all 75 million keys.  
The first thing that comes to my mind is what bugs or configuration errors exist in our program, but after I inspect the code of redisson lock and unlock, found that it seems to be a normal logic that "redisson_lock_token"  exists permanently unless been evicted.  
Lock logic , KEYS[2]) is "redisson_lock_token"
```` 
if ((redis.call('exists', KEYS[1]) == 0) or (redis.call('hexists', KEYS[1], ARGV[2]) == 1)) then
    redis.call('incr', KEYS[2]);
    redis.call('hincrby', KEYS[1], ARGV[2], 1);
    redis.call('pexpire', KEYS[1], ARGV[1]);
    return nil;
end
return redis.call('pttl', KEYS[1]);
````
