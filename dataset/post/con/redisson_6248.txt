**Context and Testing Steps:**
- We created a unit test that executes many times of lock and unlock operations to replicate the issue.
- The test uses a custom ForkJoin pool with tasks run in parallel, where each task performs a series of lock/unlock operations.
- Through testing various versions of Redisson, we found that the issue increased significantly after version 3.16.7.

#### Unit Test Code

<details>
<summary>Unit Test Code</summary>

```java
    @Test
    @SneakyThrows
    void testLock() {

        AtomicInteger unLockFailedTimes = new AtomicInteger(0);
        ForkJoinPool forkJoinPool = new ForkJoinPool(20);
        forkJoinPool.submit(() -> IntStream.range(0, 10000)
                .parallel()
                .forEach(i -> {
                    RLock lock = redissonClient.getLock(UUID.randomUUID().toString());
                    lock.lock(100, TimeUnit.MILLISECONDS);
                    // do the task ...
                    if (lock.isLocked() && lock.isHeldByCurrentThread()) {
                        try {
                            lock.unlock();
                        } catch (IllegalMonitorStateException ex) {
                            unLockFailedTimes.incrementAndGet();
                        }
                    }
                })).get();
        Version.logVersion();
        log.info("unlock failed times : {}", unLockFailedTimes.get());
    }
```

</details>

#### Observed Results by Version:

- Versions 3.15.1 to 3.16.6: The error occurs approximately 20-40 times over 10,000 lock/unlock executions.
- Version 3.16.7 and later: The error count increases to 1500-2000 times over the same number of executions.

#### Questions:

- Were any changes introduced around version 3.16.7 that could explain this increase in `IllegalMonitorStateException` occurrences?
- Do you have any recommendations on how to mitigate this issue when using Redisson versions post-3.16.7?
