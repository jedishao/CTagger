Trino commit updates to Iceberg table long after query being cancelled
# Issue
Trino commit updates to Iceberg table long after query being cancelled.

Precondition:
* Using Iceberg with Hive Metastore
* Using a relatively long `hive.metastore-timeout` (eg. `120s`)

What happened:
* During an INSERT query, Trino will try to acquire HMS lock when commit to an Iceberg table 
* This operation is a blocking call that will wait for a long time. It'll wait until it acquire the lock or `hive.metastore-timeout` happened.
* During the blocking period, query got cancelled.
* Lock being released and the commit logic continue even the query got cancelled long ago.

How this affects an user:
* User won't anticipate a commit could have happened long after a query being cancelled.
* Could mess-up retry logic implemented in the client side.

# Relevant information
Issue happened in Trino 428, but I think the issue still exist in master.
