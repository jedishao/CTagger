"RedissonShutdownException: Redisson is shutdown" error during graceful shutdown (deployment)
### Redis version

7.0.7

### Redisson version

3.32.0

### Redisson configuration

Default against AWS Elasticache, Cluster Mode disabled

### What is the Expected behavior?

No exception

### What is the Actual behavior?

During deployments of two-instance services using Redisson - when the old instances are shut down - we sometimes see different errors on the instance that either has the lock or doesn't have the lock. So far we are not able to reproduce it during deployments of single-instance services. Deployment includes graceful shutdown which includes a `lock.unlock()`. We do not see any exceptions related to a failing `unlock` call.

FYI: this is the `acquireWriteToken` method mentioned in the stack trace. [RedisWriterToken](https://github.com/factcast/factcast/blob/master/factcast-factus-redis/src/main/java/org/factcast/factus/redis/RedisWriterToken.java) is an `AutoCloseable` which includes an `unlock()` call during `close()`. `maxWait` is set to 5 minutes.

```java
  @Override
  public WriterToken acquireWriteToken(@NonNull Duration maxWait) {
    try {
      if (lock.tryLock(maxWait.toMillis(), TimeUnit.MILLISECONDS))
        return new RedisWriterToken(redisson, lock);
    } catch (InterruptedException e) {
      // assume lock unsuccessful
    }
    return null;
  }

```

### Additional information

**Had no such problems with <=3.27.1.** 

Started to see issues with 3.27.2 (with an NPE as cause). Seeing this issue's behavior (or very similar behavior) since 3.28.0 up until 3.32.0

With 3.32.0 errors seem to occur less frequent compared to 3.31.0.
