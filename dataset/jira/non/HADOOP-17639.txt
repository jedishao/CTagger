Restrict the "-skipTrash" param for accidentally deletes data
Suppose the user tries to delete the data from CLI with the "-skipTrash" param but by mistake, he deleted a couple of directories but actually, that directory user want to retain then their is no way to retrieve the delete data.
It will be good to have a confirm message like: "Skip the trash for the hdfs:///dri1/file.txt files? (Y or N)" ro we can completely disable the "-skipTrash" param.
