Topic Policies get/set not working properly
**Describe the bug**
I am managing two Pulsar Clusters that were created at version 2.8.0 and upgraded to 2.8.1. At some point one of the clusters started acting weird when editing topic specific policies.

Topics in new namespaces and old namespaces won't react to policy changes for example and return 204 or 200 with no body/empty {}
An old topic that had his policies changed in the past did work.
I put the broker on trace, when updating policies it seems the broker receives the request properly, opens a producer to __change_events and the size of that topic also grows by 1 (per update request).

This behavior persisted for over a week and is inconsistent, it is hard to tell what the conditions are.

I have not tried reseting the brokers since I want to find the root cause of the problem.

**To Reproduce**
Steps to reproduce the problematic behavior:
1. Create new topic/use an old topic
2. Get publish rate and get an empty response (expected)
3. Set publish rate to whatever
4. Get publish rate again and still receive an empty response (204/200 with empty body/empty object)

**Expected behavior**
When updating policies, getting policies will return the correct set policies and also enforce them.

 - OS: CentOS 7.8
