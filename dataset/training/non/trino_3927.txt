Support for custom DynamicConfigurationProvider
Apologies if I missed anything... I notice that presto already supports a few mechanisms to customize S3 credentials:

1. [Custom S3 Credentials Provider](https://prestosql.io/docs/current/connector/hive.html#custom-s3-credentials-provider): this allows a custom credential provider, which provides the S3 credential regardless of user identity;

2. [S3 Security Mapping](https://prestosql.io/docs/current/connector/hive.html#s3-security-mapping): this allows a per-user-identity S3 credential, but given a user-identity, the corresponding S3 credential is static.

We have a use-case where the S3 credential provider is encapsulated into a service (a.k.a., permission service). The permission service takes a user identity, and emits an S3 credential (access-key, secret-key, session-token). The S3 credential will be rotated & refreshed, so it cannot be statically configured.

What are people's opinions if we propose to expand the mechanisms 1 and 2 above, by allowing people to provide a custom [DynamicConfigurationProvider](https://github.com/prestosql/presto/blob/master/presto-hive/src/main/java/io/prestosql/plugin/hive/DynamicConfigurationProvider.java) implementation?

To be more specific, we can add a new flag, e.g., hive.s3.dynamic-configuration-provider, which points to a fully qualified class name of a custom DynamicConfigurationProvider implementation. Then have [HiveS3Module](https://github.com/prestosql/presto/blob/master/presto-hive/src/main/java/io/prestosql/plugin/hive/s3/HiveS3Module.java) bind to this implementation.

As one example of such an implementation, [updateConfiguration](https://github.com/prestosql/presto/blob/master/presto-hive/src/main/java/io/prestosql/plugin/hive/DynamicConfigurationProvider.java#L25)(Configuration configuration, HdfsContext context, URI uri) will grab user-identity from context, call out to the permission service, obtain the S3 credential, and set it in configuration.
