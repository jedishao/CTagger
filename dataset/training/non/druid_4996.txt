[Proposal] Migrating Overlord-MM management to Http.
This proposal is one of the last steps in direction of reducing dependency on Zookeeper and to make it optional. Currently RTR discovers MMs via Zookeeper based discovery (based on Announcer.announce(..)) and then uses custom protocol based on persistent znodes to manage the tasks on MMs.
The idea is to introduce a HttpRemoteTaskRunner (aka HRTR) (similar to existing [HttpServerInventoryView](https://github.com/druid-io/druid/blob/master/server/src/main/java/io/druid/client/HttpServerInventoryView.java)) which discovers MMs via ["internal-discovery"](https://github.com/druid-io/druid/blob/master/server/src/main/java/io/druid/discovery/DruidNodeDiscovery.java) interfaces and manages Tasks on MMs via Http Endpoints available on the MM. HRTR would mostly be a clone of RTR except for the interaction part.

MM would expose following HTTP endpoints.

1) HTTP endpoint to "assign" task.
MM would persist given task on disk in a "assingnedTaskDir" location, schedule the task run. When MM starts to run the task, MM would remove it from "assignedTaskDir" location. Also, MM on startup would scan "assignedTaskDir" location to schedule start of tasks what are not running/scheduled already.

2) HTTP endpoint to synchronize Worker state (disabled/enabled , tasks information) with Overlord.
MM would return its disabled/enabled state and list of all assigned/running/completed tasks it knows about. This endpoint would be implemented using the "long polling" mechanism as is used by [segment-lister endpoint ](https://github.com/druid-io/druid/blob/master/server/src/main/java/io/druid/server/http/SegmentListerResource.java#L86)so that HRTR can stay in sync without any delays.
Also, to support returning "completed" tasks in above response, MM would maintain completed tasks and their statuses on disk in a "completedTaskDir" location. MM would periodically ask Overlord about known status of locally stored completed tasks (via a newly introduced "/druid/indexer/v1/taskStatus" endpoint at Overlord) and based on that keep on cleaning up "completedTaskDir" for tasks whose completion status is already known to Overlord.

RemoteTaskRunner and WorkerTaskMonitor classes would be deprecated and eventually removed.
