[Hive Connector] Support for regional AWS STS endpoint for role assumption.
Hi,

we are currently migrating our trino setup. (Rel. 346) to an AWS EKS cluster located inside a private VPC where connection to S3 and STS is routed through regional VPC endpoints. To obtain credentials via STS, we can only connect to the regional STS endpoint (sts.eu-central-1.amazonaws.com) since the connection to the global default sts.amazonaws.com is blocked.

We could enforce the use of the regional endpoint for the hive metastore installation by setting two environment variables, which would have been picked up and considered accordingly by the AWS SDK:
 
```
 - name: AWS_DEFAULT_REGION
    value: "{{.awsRegion}}"
 - name: AWS_STS_REGIONAL_ENDPOINTS
    value: "regional"
```
This does not work for trino. Is there a way to force trino to use the regional STS endpoint similarly?

Our ultimate goal is to use trino with an IAM role provisioned through its assigned service account (https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html).

From the AWS SDK perspective, this should be possible.
