Drop partition threads not killed when query is canceled
Setup: table with a large # of partitions, each partition backed by some amount of S3 data

1) Issue `DELETE FROM table`
2) By default, 20 threads (`hive.max-concurrent-metastore-drops`) will try to delete 20 partitions in parallel
3) Cancel the query
4) Issue a delete against any other table.  It won't be able to as the 20 threads are still trying to DELETE.  No other partitions can be dropped until the original threads complete.
