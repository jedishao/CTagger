JDK8 regression similar to #1169 with http2 enabled proxy. Slow exit
Similar to #1169 but for java8 clients using the trino-jdbc driver. This PR appears to have caused the issue:
https://github.com/trinodb/trino/pull/5915

trino-jdbc 354 doesn't have this problem but trino-jdbc >= 355 does. 

It appears that this code wasn't unnecessary on jre <=11. We are testing on 1.8.0_281 and seeing this issue.

We are seeing shutdown times of 5 minutes (basically the okhttp connection timeout) from command line/console applications after the last query finishes. The application hangs for five minutes and two threads are active for OKHttp.
