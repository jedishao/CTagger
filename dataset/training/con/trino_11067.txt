Metadata access failures are shared even if cache disabled
Affects `CachingJdbcClient`, but necessarily only that.

Even if caching is disabled (default), the guava Cache used by CachingJdbcClient (via `EvictabeCache`) makes concurrent loads of the same key synchronized. This looks like a nice feature, but

- caching may be disabled because data shouldn't be shared; data is still shared between threads in these edge cases
- failures are shared too
  - eg in `CachingJdbcClient`, one `session` may fail to access a table, but some other session would access it. it may happen that the other gets and propagates a failure that the first session experienced
