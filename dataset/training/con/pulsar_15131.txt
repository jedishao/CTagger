Get deadlock if create topic fails
**To Reproduce**
Steps to reproduce the behavior:
1. setup a remote cluster for a namespace
2. delete the remote cluster from cluster list and keep namespace unchanged
3. start a consumer or producer for a new topic which under the namespace above
4. See log `Failed to subscribe to topic on xxx` and the deadlock showed up

**Describe the bug**
I reproduced with current master HEAD version (2f74d8ee8e1706d0a92e641d9e5f94bf9f14e655), it may also reproduce with other code branch e.g. checkDeduplicationStatus fail

When create a persistent topic, it first acquire a w lock under the hood `topics.computeIfAbsent`, and then try acquire another w lock to remove the corresponding entry from the `topics` map if create topic fails.
