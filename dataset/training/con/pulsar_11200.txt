Metadata cache inconsistency across brokers (race condition)
**Describe the bug**

When a metadata store resource is updated using pulsar-admin, the broker that handles the update works fine. But some times on one of the other brokers, the getData() can return stale data in the cache. This results in that broker being out of sync forever (if there are no further updates) or being a step behind (if there are subsequent updates).

**To Reproduce**
Steps to reproduce the behavior:

GitHub issue


# Start two instances of pulsar broker in two separate terminals

PULSAR_BROKER_CONF=~/conf/broker-1.conf bin/pulsar broker
PULSAR_BROKER_CONF=~/conf/broker-2.conf bin/pulsar broker

# All admin commands are directed to broker-1 using the URL of broker-1

# Create a tenant and a namespace (URL of broker-1)

bin/pulsar-admin --admin-url http://localhost:8081 tenants create rgtenant

bin/pulsar-admin --admin-url http://localhost:8081 namespaces create rgtenant/rgnamespace

# Create a resource group
bin/pulsar-admin --admin-url http://localhost:8081 resourcegroups create -bd 10000 -md 100 -bp 10000 -mp 100 test1

# Attach the namespace to the resource group
bin/pulsar-admin --admin-url http://localhost:8082 namespaces set-resource-group -rgn test1 rgtenant/rgnamespace
